# SciForge User Manual

In SciForge, you can open a project, let the AI read materials, modify files, run analyses, and create figures, then check the results and request changes. The files, conversations, and run records from a task remain available for review and for later collaboration.

If this is your first time, start with the [five-minute quickstart](./getting-started/five-minute-quickstart.md). If you already have a specific question, use the outline below to find the right page; there is no need to read the whole manual from beginning to end.

| --- | --- | --- |

| **Workbench guides** | You want to know where a button is or how to hand files to the AI | Workspaces and sessions, adding attachments, file preview, panel layout, Terminal and Browser Preview, as well as how to describe a task and check results. |
| **Features & Extensions** | You need to complete a particular kind of research work | Scientific file preview, plotting and comments, versions and research records, team collaboration, notes, scheduled tasks, and extensions. |
| **Case tutorials** | You want to see how a complete task is done | From input data through running an analysis, revising results, and delivering them; includes scientific plotting, multi-person RNA-seq collaboration, and virtual cell cases. |
| **Settings & security** | You need to adjust file access, tool permissions, or connected services | File and network access, action confirmations, and the conditions for using remote resources and team collaboration. |
| **Reference & troubleshooting** | You hit an error or a version mismatch, or need to look up installation requirements | Troubleshooting, versions and compatibility, feature limits, and extension licenses. |

## A few names to start with

A **workspace** is the project directory you open. Which files the AI works on and where the Terminal runs both depend on it.

A **session** is a conversation centered on a specific task. One project can have many sessions; keeping different goals in separate sessions makes them easier to pick up later.

The **Runtime (execution runtime)** is the program that actually handles tasks. You can choose Codex, Claude Code, or DSH, then connect models and tools according to the instructions for each, see [Runtime and model access](./getting-started/runtime-and-models.md).

**Research records** hold a task's intermediate results and the basis for them. Once you have completed your first task, look into checkpoints, the Evidence DAG, and research dossiers as needed.
