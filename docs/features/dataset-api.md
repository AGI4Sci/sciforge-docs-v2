# 数据集 API（Dataset API）

数据集 API 是工作区级的数据接入与整理层：把公共生物数据库、私有对象存储和派生数据集登记成可治理的数据源，再用计划式流程完成获取、整理、校验与发布。它适合在“找数据、取数据、整理成可复现数据集”阶段使用，与生命科学预览、Create Loop 配合。

## 打开方式

- 入口：会话中的数据集结果卡；Create Loop 的资源面板。自定义端点与对象存储连接只能通过界面登记，并需要确认。
- 作用对象：当前工作区及其 `.sciforge/datasets` 数据源注册表。
- 前提：数据源地址可访问；需要认证时通过环境变量引用凭据；S3 兼容存储需先登记服务地址、存储桶与允许前缀。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 查找公共生物数据源 | 浏览内置生物提供方目录，核对元数据、原始数据端点与认证要求 | 带适配方式说明的目录条目 |
| 获取元数据或原始数据 | 按已登记端点发起带大小限制的请求，选择元数据或原始数据 | 带 SHA-256、来源清单与请求回执的派生文件，以及片段预览 |
| 浏览对象存储 | 登记 S3 兼容存储后列对象、读对象头、按范围下载 | 以校验和命名的对象副本与元数据 |
| 计划式整理数据 | 生成准备计划，审核并确认后执行 | 不可变计划、运行检查点、派生数据集与来源清单 |
| 质量校验与发布 | 运行校验，再发布 | 可复现的数据集版本与 `data-construction-pipeline.md` |

**不执行什么：** 不执行任意 shell、SQL 或 Python，也不把模型生成的代码当作处理逻辑。所有整理步骤由数据集 API 按严格 JSON 参数确定性地完成；失败应通过数据集 API 重试或恢复，而不是绕到终端用 `curl` 直连。

## 典型流程

1. 在目录中选定提供方，确认端点、认证方式和适配类型；不要只看目录条目就假定适配器已实现。
2. 由界面完成自定义端点或对象存储登记；Agent 不能自行添加任意端点，只能使用已登记来源 ID。
3. 获取元数据或原始数据，核对校验和、字节范围与来源回执。
4. 生成准备计划，先审阅计划附带的数据构造管线，再确认并执行。
5. 失败时用不可变计划标识与运行标识恢复；完成后运行校验，发布前确认校验报告覆盖同一路径与 SHA-256。

## 输入、输出与权限

- 读取：工作区数据源注册表、公共目录、已登记 API 响应与对象存储对象。
- 写入：注册表、运行状态、带校验和的派生产物、来源清单与发布版本；源文件不被覆盖。
- 审批或外部影响：自定义端点与对象存储登记、计划确认需要确认；预置提供方登记、普通获取和整理按工作区写入执行。
- 不会做什么：不保存凭据明文，不执行任意代码，不把通用来源变成任意 URL 代理，也不静默覆盖已存在内容。

## 已知限制

- 目录条目只描述访问方式，不代表对应适配器已经实现。
- 通用登记来源的请求只允许 GET，并受超时、响应大小、跨域重定向和 HTTPS 限制；例外只有白名单内的 UniProt ID 映射 POST。
- 对象存储目前是 S3 兼容接口：列表每页最多 1,000 个键，下载默认上限 256 MiB；HTTPS 默认开启，内部 HTTP 需显式确认。
- 公共数据库的可用性、限流和字段变化不受 SciForge 控制，失败以结构化回执返回。
- 原始下载按字节保存，不解析、不转换源数据；需要科学解读时交给预览或分析步骤。
