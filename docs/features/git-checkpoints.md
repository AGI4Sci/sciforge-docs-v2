# Git 检查点（Git Checkpoints）

Git Checkpoints 在任务回合前后记录工作区的 Git 快照，把“这一轮开始前和完成后代码是什么状态”固定下来。它只负责检查点元数据与恢复策略，实际仓库操作通过通用版本控制能力执行；研究上下文本身由 [Research Checkpoints](./research-checkpoints.md) 记录。

## 打开方式

- 入口：顶部工具栏 **Git Checkpoints**；右侧面板标题同为 **Git Checkpoints**。
- 作用对象：当前会话绑定的本地 Git 工作区。
- 前提：工作区是 Git 仓库，且版本控制提供方可用；非 Git 工作区不会产生检查点。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 查看回合检查点 | 打开面板，按时间查看回合前后的记录 | 检查点列表与阶段 |
| 核对改动范围 | 选择检查点，查看工作区 patch 与变更摘要 | 差异预览 |
| 恢复到已知状态 | 选择目标检查点，点击 **恢复** 并确认 | 回到该快照的工作区 |
| 避免恢复丢状态 | 不需要额外操作；系统在恢复前自动捕获 | 救援检查点 ID |
| 刷新当前列表 | 点击刷新图标重新读取 | 最新检查点列表 |

## 典型流程

1. 在 Git 工作区中开始一个任务，系统记录回合前检查点。
2. 完成或结束回合后刷新面板，确认出现回合后检查点。
3. 选择目标检查点，先看 patch 预览，再决定是否恢复。
4. 需要恢复时点击 **恢复** 并确认，等待系统先创建救援检查点。
5. 恢复完成后重新核对工作区状态与 [变更](./change-inspector.md) 面板。

## 输入、输出与权限

- 读取：工作区 Git 状态、快照元数据、patch 与变更摘要。
- 写入：检查点元数据写入应用数据目录；恢复会改写工作区文件。
- 审批或外部影响：恢复是破坏性操作，必须显式确认；救援检查点创建失败时恢复中止。
- 不会做什么：不直接执行 Git 命令或绕过版本控制提供方策略，也不在非 Git 工作区伪造检查点。

## 已知限制

- 当前实现范围覆盖本地 Git 工作区的回合边界检查点；面板提供列表、预览、刷新与恢复。
- 面板没有手工创建检查点的按钮，检查点由回合生命周期触发，不依赖面板停留或手动保存。
- patch 预览可能被版本控制提供方截断，此时只能看到部分差异。
- 恢复是工作区级回退，不是只读比较；救援检查点是恢复前自动留下的保护点。
- 它不保存研究问题、来源或恢复位置，因此不能替代 Research Checkpoint。
