# 远程 SSH

Remote SSH 用普通 OpenSSH 别名把实验室主机、GPU 节点或集群目录接入 SciForge。文件、终端、Git 和 Agent 请求通过受控 SSH 路径发往远端，界面仍留在本机。当前成熟度为 **部分可用**：主路径可以连接远程工作区，复杂 Git、快照和文件操作需要逐项验证。

## 打开方式

- 入口：顶部工具栏或右侧面板的 **远程资源**。
- 作用对象：当前工作区可绑定的远程目标，以及从工作区位置菜单选择的远端项目目录。
- 前提：系统 OpenSSH 可用；目标别名已在 OpenSSH 配置中可连接；VPN 与 MFA 由用户完成。
- 环境：Apple silicon 上默认使用 UTM ARM64 虚拟机承载实验室 VPN；Docker 是高级路径，VirtualBox 用于既有非 macOS 部署。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 登记实验室与目标 | 创建实验室、选择环境并提供普通 SSH 别名 | 可探测的远程目标 |
| 测试完整路径 | 在面板中探测目标 | 分类的连接结果、延迟与诊断 |
| 打开远程工作区 | 从工作区位置选择目标与项目目录 | 以远端目录为根的工作区 |
| 运行受限操作 | 经审批执行命令、上传或下载 | 有界输出、传输结果与退出状态 |

## 典型流程

1. 在 **远程资源** 中创建实验室并选择环境；UTM 虚拟机需已安装并运行 OpenSSH Server。
2. 打开虚拟机控制台，由你完成 aTrust/VPN 登录与 MFA；SciForge 不保存这些凭据。
3. 登记最终目标的普通 OpenSSH 别名，探测虚拟机、VPN 与最终目标的完整路径。
4. 将该目标授权给当前工作区，再从工作区位置菜单选择远端项目目录。
5. 新建会话，先运行只读任务，确认文件、Git 和终端确实作用于远端。

## 输入、输出与权限

- 读取：目标状态、探测结果、远端目录、文件、Git 状态与差异，以及受控命令输出。
- 写入：上传、下载、命令执行、目标与实验室配置，以及工作区绑定；上传下载默认上限为 64 MiB。
- 审批或外部影响：所有非只读操作都需要确认和幂等键；命令执行按破坏性操作治理，上传属于外部写入，下载属于工作区写入。
- 凭据与主机信任：SSH 密钥、VPN 凭据和 MFA 留在用户或系统安全设施中；SciForge 不会自动接受新的主机密钥。
- 不会做什么：不绕过配置的 SSH 路径、不向渲染进程暴露原始 SSH 流、不启用 Agent 转发，也不提供任意隧道或透明网络代理。

## 已知限制

- 功能状态为 **部分可用**：复杂 Git、快照和文件操作需要逐项验证。
- 当前远端工作区以 Linux x64 为主；命令执行要求目标有 POSIX `sh`，远程 Git 首期只提供 status 与 diff。
- 受控终端在远端基于管道，不宣称完整伪终端（PTY）兼容；取消本地 SSH 进程不保证终止远端子进程。
- 远程文件、终端和 Agent 命令实际作用于远端目录；本地窗口不代表数据已经复制到本机。
- 远程 Codex 需要模型 API 或 Model Router 可用；Claude 的远端放置尚未列为支持范围。
- 长任务应提交给 Slurm 等远程调度器，不要依赖 SSH 连接一直存活。
