# 科学绘图（Scientific Plotting）

科学绘图解决“这张图从哪来、能不能重画”的问题。它处在数据分析与交付之间：Agent 负责理解任务和准备数据，绘图插件负责受治理的确定性渲染，并把每个正式图表固定为一个可审查的产物版本。

## 打开方式

- 入口：右侧面板 **图表溯源**（Plot Provenance）；选中科学图表或渲染 Manifest 资源时打开对应版本。发起绘图时，在会话中说明数据、图表类型与统计口径，由 Agent 选择代码图或混合图路线。
- 作用对象：当前工作区中的结构化数据、图表产物与渲染 Manifest。
- 前提：工作区可用；本机绘图 Worker 与 Python/Matplotlib 环境正常。Worker 不可用时可以查看已有版本，但无法新渲染或复跑。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 把数据映射成图表配方 | 说明输入文件、列名、分组与统计定义，让 Agent 先做数据映射 | 含数据、转换与统计定义的 Recipe |
| 生成正式图表 | 确认配方后提交渲染，由 Worker 确定性执行 | PNG、代码、环境、日志与 Manifest |
| 固定这次结果 | 每次正式渲染提交一个不可变的 Artifact Version | 可引用的图表版本 |
| 查看单图技术链 | 在 **图表溯源** 的 **预览**、**复现**、**证据**、**版本** 间切换 | 数据、统计、转换、参数、环境、执行与审核记录 |
| 复跑或比较 | 用 **按精确 Recipe 复跑** 或 **比较 Manifest**，选择另一个不可变版本 | 复现结论或逐部分差异 |

## 典型流程

1. 把输入数据放入工作区，确认列名、单位、分组、缺失值规则和统计口径。
2. 在会话中提出图表需求；Agent 选择代码图或混合图路线，完成数据映射并让你确认 Recipe。
3. 提交正式渲染。Worker 输出 PNG、可执行代码、环境指纹、执行日志和渲染 Manifest，并把本次结果提交为一个 Artifact Version。
4. 在右侧 **图表溯源** 核对数据来源、统计定义、转换步骤、参数、环境和审核状态；需要对外展示时使用 **打开大图预览** 或 **打开产物版本历史**。
5. 需要复核时，选择 **按精确 Recipe 复跑**，或用 **比较 Manifest** 与另一个版本比较；结果显示复现一致或具体哪些部分发生变化。

复跑与重试使用 `operationId` 去重：网络中断后重试同一请求，会复用同一标识与已准备的字节，只回放一次提交，不会多出第二个 Figure 版本；用同一标识提交不同内容会被拒绝。

## 输入、输出与权限

- 读取：工作区中的数据文件、结构化输入、已有图表版本与渲染 Manifest。
- 写入：工作区内生成 PNG、Recipe、Manifest 与执行日志；每次正式渲染新增一个 Artifact Version。
- 审批或外部影响：绘图在本机 Worker 中执行，不上传数据；不需要额外确认，但会写入工作区并留下版本记录。
- 不会做什么：不生成模型图片，也不把模型回执当作正式绘图 Manifest；不把工作区路径或“最新版本”指针当作版本真相。

## 已知限制

- 功能状态表将本插件列为**部分可用**；能否渲染取决于本机 Worker、Python 与 Matplotlib 依赖是否就绪。
- 当前正式渲染以 PNG 作为版本化输出；需要正式复现保存时，输入必须是固定的 Artifact Version 引用，不能用 `latest` 替代。
- 复跑需要同时具备精确的 Figure 与 Recipe 版本；缺少任一版本时面板会显示 **无法复跑**。
- 模板覆盖折线、散点、柱状、误差条、热图、多面板等常见科研图；模板之外的图形不应当作“已支持”承诺。
- 模型生成的插图、示意图和照片不属于本插件；它们由图像生成链路负责，需要人工接受时转到图片审改。
