# 科研图件（Scientific Figures）

**选择文件 → 告诉 AI 怎么画 → 查看结果 → 满意后接受。** 科研图件将文字要求、Python 代码、实际运行与图片版本关联起来。修改图件时，在输入框中描述需要调整的内容。

:::info 使用前准备
使用前请准备Python和Matplotlib。当前支持Python绘图，暂不支持R和MATLAB。
:::

多文件清洗、四面板图、缺失值矩阵与失败恢复的实际操作和截图，见 [复杂科研图件案例](../cases/scientific-figures-complex.md)。

## 安装与打开

1. 在 **扩展 → 市场** 找到与你的 SciForge 版本兼容的科研图件包，核对发布者和权限，批准安装并启用。未上架时需由维护者提供签名包及对应安装来源。
2. 打开一个可写的本地工作区和已配置模型的 **DSH 会话**。
3. 在 SciForge 中从右侧栏插件选择器选择 **科研图件**；原生 DSH 中使用会话输入区的 **Figures** 面板，或输入 `/scientific-figures`。默认 **图件** 页面包含文件输入、文字输入与图片预览。

先确认所选Python已安装Matplotlib，再运行一个简单绘图任务检查环境。可在插件配置中用 `pythonCommand` 指定解释器。

原生 DSH 要求 `>=0.2.1-rc.4 <0.3.0`、Node >=22。SciForge 适配入口当前只在通过隔离检查的 macOS 环境执行；Windows 与 Linux 的执行限制不会因插件安装成功而消失。安装包包含本平台的原生 Canvas 组件，换平台、架构或 Linux libc 时需要对应构建。

## 从数据与代码开始

**数据和代码是复现的核心，图片是某次运行的结果。** 在 **新建** 选择两种起点之一：

| 开始方式 | 必须提供 | 接下来发生什么 |
| --- | --- | --- |
| **从数据开始**（推荐） | 数据文件、绘图要求 | AI 检查数据，编写代码，保存本次数据副本，实际运行并创建首图。 |
| **已有数据和代码** | 数据文件、Python 代码、要求 | 保存已有代码与数据快照，先运行建立基线；已有图片可选作比较。 |

点击 **开始绘图** 后，在左侧会话核对运行；完成后刷新并选择图件。后续在 **图件** 页继续打字修改，不需要重新导入每一份原始数据。

```text
读取 data/trend.csv，用 time 作为横轴，response 作为纵轴。
画蓝色折线图，坐标轴标明单位。不要补造数据。
冻结本步数据和代码并实际运行；后续修改先生成候选，等我确认。
```

文件选择是工作区文件引用，不是浏览器上传入口。只有图片时不能恢复精确数据。提供的原图会标为“用户提供、尚未验证”，与保存的代码及输入关联；不伪造历史成功运行。真实运行的结果作为独立版本保留。

![真实科研图件新建入口：从数据或已有数据和代码开始](/img/docs/scientific-figures/04-data-code-start.png)

## 每一步保存什么

| 记录 | 保存方式 |
| --- | --- |
| 数据 | 每个代码版本保存独立的数据副本与原始路径。后续版本默认沿用这份副本，原文件改变后，已保存版本的数据仍保留。 |
| 代码与参数 | 完整源文件、入口、参数和父版本关系，不覆盖旧版本。 |
| 运行环境 | Python/Matplotlib 版本、实现、解释器名称、平台/架构及已安装 Python 包版本清单。 |
| 运行与产物 | 每次运行分别保存状态、退出码、日志，以及 PNG、CSV、TSV、JSON、TXT 输出，并记录文件路径与校验信息。日志有长度限制。 |
| 环境重建文件 | 成功运行自动保存 `_environment/requirements.txt`（精确版本）、`environment.json` 和 `REBUILD.md`。 |
| 历史 | 代码、数据、运行、原图和候选均保留；接受候选后，它成为当前图，仍可在 **历史版本** 查看以前的图。 |

修改代码但不换数据时，默认继承已冻结输入。需要使用更新后的数据，在高级设置勾选 **重新读取工作区数据**，形成新版本。数据清洗、筛选或变换若要供下一步使用，必须先保存结果文件并纳入下一版本输入快照；插件不会自动捕获整个工作区或 Python 内存中的任意变量。

重新运行指定版本时使用它保存的代码、参数和数据副本；原文件改写或删除后，仍使用该版本保存的内容。

## 保存分析产物、分页与恢复

脚本将清洗数据、统计结果写入 `SCIENTIFIC_FIGURES_OUTPUT_DIR`，与图片一起保存。例如 `cleaned.csv`、`summary.json` 和 `rules.txt`。CSV/TSV/TXT 必须是有效 UTF-8，JSON 必须可解析；出错会明确失败，不把坏文件当作成功结果。PNG 上限仍为 16 个、单个 20 MiB、合计 64 MiB；分析文件独立限制为 32 个、单个 8 MiB、合计 32 MiB。

下一步使用已保存文件时，将工作区相对路径 `.scientific-figures/` 加运行返回的 `output.path`，放入新代码版本的 `inputPaths`。该步骤会为新版本保存一份输入副本，不需要人工把暂存文件另存到工作区。**只有 PNG 能发布为图件**，数据文件仍可选中查看保存路径与摘要。

**代码与运行** 默认每页显示 20 条摘要，点击 **更多代码版本 / 更多运行记录** 继续加载；只有读取选中记录时才取完整内容与验证文件。损坏条目显示局部错误，不应阻断其他页面或中断记录入口。

已终止进程的可信结果会先保存，再收集和提交产物；提交成功后才清理暂存。**尚未结束或中断的运行** 中，只有存在可信进程结果的条目提供 **完成中断记录**：复用原结果完成提交，不重新运行 Python。没有结果、进程未确认停止或残留锁时需检查，插件不会猜测成功、抢锁或自动重跑。

## 环境重建

每次成功运行的 `_environment` 目录保存：精确包版本清单、Python/平台/架构信息，以及创建虚拟环境和安装依赖的说明。

按REBUILD.md创建独立环境并安装记录中的依赖。更换系统或Python版本后，需要重新检查结果；系统库和驱动需自行准备。

## 修改、比较与接受

继续用文字描述修改，例如“保留数据，把线改为蓝色，标题缩短”。AI 应保存新的代码版本、实际运行，并把输出发布为候选图。

- **当前图 / 修改后**：检查当前版本与所选候选。存在多个候选时，从 **候选** 下拉框切换。
- **申请接受**：把接受请求送入会话；在会话中核对候选图，再点击 **允许**，当前图才会更新。
- **保留当前图**：拒绝所选候选，继续使用当前图。

查看候选图后，点击 **申请接受**，再在会话中点击 **允许**，将它设为当前版本。接受后原图和历史代码、运行仍保留。图件发生变化后，旧候选可能失去基线，需要重新生成。

## 查看代码与运行

需要核对过程时打开 **代码与运行**，普通绘图无需先读这些信息。

1. 选择版本并 **载入版本**，查看 Python 源码。
2. 修改后点击 **保存并冻结代码**，得到新的子版本；不会覆盖旧代码。
3. 点击 **执行已冻结 Python**，查看运行状态、退出码与输出。参数、输入路径、源码比较、环境与日志按需展开。
4. 成功输出可以发布为新图件或现有图件的候选；发布候选前需读取并选定当前基线。

也可展开 **所有版本与来源**，从具体图件进入关联的代码与运行记录。

![真实代码与运行界面，展示已载入的 Python 子版本](/img/docs/scientific-figures/02-code-and-run.png)

## 案例：修改一张折线图并正式接受

下面用一组演示数据修改折线图，并保存接受后的结果。示例使用MVP.10，运行于macOS arm64和DSH。

### 1. 准备数据和要求

已有折线图的横轴为 `[1, 2, 3]`、纵轴为 `[1, 3, 8]`。在面板提供已有 Python 文件，并要求保存新子版本，将纵轴改为 `[2, 4, 7]`，实际运行后发布候选，暂不接受。

```text
基于当前折线图的 Python 代码，保留横轴，
把 y 改成 [2, 4, 7]，保存为新的子版本并实际运行。
先发布为候选图，不要自动接受。
```

### 2. 核对实际产出

| 项目 | 实测结果 |
| --- | --- |
| 新代码版本 | `chat-mvp-v5-20261105`，保留父版本关系 |
| 运行 | `chat-mvp-run-v5-20261105` |
| 运行结果 | `completed`，退出码 `0` |
| 环境 | Python `3.14.7`、Matplotlib `3.11.2` |
| 输出 | PNG，960 × 720，31,384 字节 |
| 候选 | `r-ee889dbf7bff5aa71d3732541fa9d5a6` |

在聊天中查看本次运行生成的图片。

![真实聊天自动附件中的折线图](/img/docs/scientific-figures/03-chat-attachment.png)

### 3. 确认接受并重启检查

从面板点击 **申请接受**，在会话中核对候选并点击 **允许**。批准后，文档修订变为 `7`，上述候选成为当前图；原图继续保留。随后退出并重新启动 SciForge，聊天框、文件入口和已接受图件均恢复，图片仍能正常加载。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| AI 已完成，面板还是旧图 | 点击 **刷新**，检查图件和候选选择。 |
| 发送失败 | 确认当前有可用的 DSH 会话及模型连接；保留输入，待会话恢复后重试。 |
| Python 或 Matplotlib 不可用 | 查看 **代码与运行** 的错误，配置正确解释器和依赖后使用新运行重试。 |
| 图片自动附件显示 `File not found` | 请AI重新读取对应运行；仍无法显示时，检查图片文件是否存在，并确认插件版本。 |
| 无法接受候选 | 检查是否已在会话中点击 **允许**，以及当前图是否已改变；必要时重新生成候选。 |
| 运行失败仍想发布图片 | 先修复并成功运行；失败运行不能发布为正式候选。 |

## 当前范围与边界

- 已实现 Python + Matplotlib、PNG 与 CSV/TSV/JSON/TXT 产物保存、代码快照、依赖固定版本文件、分页历史、中断提交恢复、图件关联和正式接受。暂不支持运行 R。
- 输入为工作区文件。绘图成功后需手动刷新；本机依赖与模型服务需自行配置。
- 记录保存在当前工作区 `.scientific-figures/`，需要在其他产物或证据面板中使用时，应另行整理关联记录。
- 首次会话工作区限定可写范围；切换目录不会扩大权限。只读环境、隔离不可用或工作区位于系统临时目录时会拒绝运行。
- 本地 Python 有写入隔离，但不等于禁止全局读取或网络。模型请求也受所用模型服务的数据策略影响，不应声称“数据绝不外发”。只执行可信代码。
