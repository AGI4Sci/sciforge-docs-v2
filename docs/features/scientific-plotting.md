# 科研图件（Scientific Figures）

**选择文件 → 告诉 AI 怎么画 → 查看结果 → 满意后接受。** 科研图件将文字要求、Python 代码、实际运行与图片版本关联起来。修改图片时继续打字说明即可，不需要在图片上框选、画箭头或放置图钉。

:::info 当前版本
本页根据 `@sciforge/plugin-scientific-plotting` **0.4.0-mvp.9** 的真实本地验收更新（2026-11-05）。已验证 macOS arm64、DSH Runtime、Python + Matplotlib；这是本地签名 MVP 的能力说明，不表示该版本已在公共市场向所有用户发布。R 执行尚未实现。
:::

多文件清洗、四面板图、缺失值矩阵与失败恢复的实际操作和截图，见 [复杂科研图件案例](../cases/scientific-figures-complex.md)。

## 安装与打开

1. 在 **扩展 → 市场** 找到与你的 SciForge 版本兼容的科研图件包，核对发布者和权限，批准安装并启用。未上架时需由维护者提供签名包及对应安装来源。
2. 打开一个可写的本地工作区和已配置模型的 **DSH 会话**。
3. 从右侧栏插件选择器选择 **科研图件**。默认 **图件** 页面包含文件输入、文字输入与图片预览。

本机需要可用的 Python 和 Matplotlib。插件不会自动安装依赖；Python 不可用、缺少 Matplotlib 或运行失败时，请先处理运行日志中的具体错误。

## 从数据与代码开始

**数据和代码是复现的核心，图片是某次运行的结果。** 在 **新建** 选择两种起点之一：

| 开始方式 | 必须提供 | 接下来发生什么 |
| --- | --- | --- |
| **从数据开始**（推荐） | 数据文件、绘图要求 | AI 检查数据，编写代码，冻结输入，真实运行并创建首图。 |
| **已有数据和代码** | 数据文件、Python 代码、要求 | 保存已有代码与数据快照，先运行建立基线；已有图片可选作比较。 |

点击 **开始绘图** 后，在左侧会话核对运行；完成后刷新并选择图件。后续在 **图件** 页继续打字修改，不需要重新导入每一份原始数据。

```text
读取 data/trend.csv，用 time 作为横轴，response 作为纵轴。
画蓝色折线图，坐标轴标明单位。不要补造数据。
冻结本步数据和代码并实际运行；后续修改先生成候选，等我确认。
```

文件选择是工作区文件引用，不是浏览器上传入口。只有图片时不能恢复精确数据。提供的原图会标为“用户提供、尚未验证”，与保存的代码及输入关联；不伪造历史成功运行。真实运行的结果作为独立版本保留。

![真实科研图件新建入口：从数据或已有数据和代码开始](/img/docs/scientific-figures/04-data-code-start.png)

## 每一步保存什么

| 记录 | 保存方式 |
| --- | --- |
| 数据 | 每个代码版本有独立的输入字节快照、原相对路径、SHA-256 和长度。子版本默认复制父版本冻结数据，不重新读取可变工作区文件。 |
| 代码与参数 | 完整源文件、入口、参数和父版本关系，不覆盖旧版本。 |
| 运行环境 | Python/Matplotlib 版本、实现、解释器名称、平台/架构及已安装 Python 包版本清单。 |
| 运行与图片 | 每次运行使用新 ID，保存状态、退出码、受限长度日志和 PNG 输出；关联具体代码与输入。 |
| 历史 | 代码、数据、运行、原图和候选均保留；**历史版本**可查看以前的图。接受只改变当前图指针。 |

修改代码但不换数据时，默认继承已冻结输入。需要使用更新后的数据，在高级设置勾选 **重新读取工作区数据**，形成新版本。数据清洗、筛选或变换若要供下一步使用，必须先保存结果文件并纳入下一版本输入快照；插件不会自动捕获整个工作区或 Python 内存中的任意变量。

复跑指定版本时使用它保存的代码、参数和数据字节；旧源文件改写或删除，不应改变已保存快照。环境清单帮助核查依赖，但不是可移植容器、软件包二进制归档或完整锁文件，不保证跨平台图片摘要一致。

## 修改、比较与接受

继续用文字描述修改，例如“保留数据，把线改为蓝色，标题缩短”。AI 应保存新的代码版本、实际运行，并把输出发布为候选图。

- **当前图 / 修改后**：检查当前版本与所选候选。存在多个候选时，从 **候选** 下拉框切换。
- **申请接受**：把接受请求送入会话，等待宿主正式审批。确认对象后点击审批中的 **允许**，当前图才会更新。
- **保留当前图**：拒绝所选候选，继续使用当前图。

生成、发布候选和正式接受是三个步骤。AI 回复“已完成”不等于已接受；以实际操作结果为准。接受后原图和历史代码、运行仍保留。图件发生变化后，旧候选可能失去基线，需要重新生成。

## 查看代码与运行

需要核对过程时打开 **代码与运行**，普通绘图无需先读这些信息。

1. 选择版本并 **载入版本**，查看 Python 源码。
2. 修改后点击 **保存并冻结代码**，得到新的子版本；不会覆盖旧代码。
3. 点击 **执行已冻结 Python**，查看运行状态、退出码与输出。参数、输入路径、源码比较、环境与日志按需展开。
4. 成功输出可以发布为新图件或现有图件的候选；发布候选前需读取并选定当前基线。

也可展开 **所有版本与来源**，从具体图件进入关联的代码与运行记录。

![真实代码与运行界面，展示已载入的 Python 子版本](/img/docs/scientific-figures/02-code-and-run.png)

## 案例：修改一张折线图并正式接受

这是 **2026-11-05 的真实应用验收案例**，数据为演示数值，不代表科研实验结论。它验证了“聊天要求 → 冻结代码 → 实际 Python → 候选图 → 正式审批 → 重启恢复”。

### 1. 准备数据和要求

已有折线图的横轴为 `[1, 2, 3]`、纵轴为 `[1, 3, 8]`。在面板提供已有 Python 文件，并要求保存新子版本，将纵轴改为 `[2, 4, 7]`，实际运行后发布候选，暂不接受。

```text
基于当前折线图的 Python 代码，保留横轴，
把 y 改成 [2, 4, 7]，保存为新的子版本并实际运行。
先发布为候选图，不要自动接受。
```

### 2. 核对实际产出

| 项目 | 实测结果 |
| --- | --- |
| 新代码版本 | `chat-mvp-v5-20261105`，保留父版本关系 |
| 运行 | `chat-mvp-run-v5-20261105` |
| 运行结果 | `completed`，退出码 `0` |
| 环境 | Python `3.14.7`、Matplotlib `3.11.2` |
| 输出 | PNG，960 × 720，31,384 字节 |
| 候选 | `r-ee889dbf7bff5aa71d3732541fa9d5a6` |

聊天自动图片附件已在 **0.4.0-mvp.6** 真实验证成功：再次读取该运行后，图片正常解码显示。截图取自实际聊天附件，未重新绘制。

![真实聊天自动附件中的折线图](/img/docs/scientific-figures/03-chat-attachment.png)

### 3. 确认接受并重启检查

从面板点击 **申请接受**，会话触发宿主正式审批。批准后，文档修订变为 `7`，当前图指向上述候选；原图继续保留。随后退出并重新启动 SciForge，聊天框、文件入口和已接受图件均恢复，图片仍能正常加载。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| AI 已完成，面板还是旧图 | 点击 **刷新**，检查图件和候选选择。 |
| 发送失败 | 确认当前有可用的 DSH 会话及模型连接；保留输入，待会话恢复后重试。 |
| Python 或 Matplotlib 不可用 | 查看 **代码与运行** 的错误，配置正确解释器和依赖后使用新运行重试。 |
| 图片自动附件显示 `File not found` | 更新至包含 0.4.0-mvp.6 修复的兼容版本；请 AI 重新读取该运行。旧消息已保存的错误路径不会自动重写。 |
| 无法接受候选 | 检查正式审批是否完成，以及当前文档/基线是否改变；不要手工补审批字段。 |
| 运行失败仍想发布图片 | 先修复并成功运行；失败运行不能发布为正式候选。 |

## 当前范围与边界

- 已实现 Python + Matplotlib、PNG 输出、代码快照、运行日志、图件关联和正式接受。R 保留执行器边界，未实现运行。
- 输入为工作区文件。绘图成功后需手动刷新；本机依赖与模型服务需自行配置。
- 不再提供图上框选、箭头、圈画或图钉批注。图片审改等其他独立扩展不受本页改变影响。
- 本地 Python 有写入隔离，但不等于禁止全局读取或网络。模型请求也受所用模型服务的数据策略影响，不应声称“数据绝不外发”。只执行可信代码。
- 本案例覆盖代表性本地路径，不承诺所有平台、Runtime 或环境下像素级一致的复现。
