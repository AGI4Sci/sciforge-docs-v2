# Create Loop（多步流程）

先跑一条小流程：给 AI 一段测试文字，让它生成三条摘要，再由你检查是否通过。跑通后，可以在人工审批之后接上写文件或发送请求的步骤。

## 打开方式

在最右侧工具栏点 **创建 Loop**。入口未显示时展开 **更多工具**。看到画布后，新建并命名 Loop，检查右侧设置中的工作目录。AI、图片和代码节点使用该目录。定义和运行记录保存在本机。

## 典型流程

这条试跑把三条摘要交给你审阅，通过后才送到 **输出** 节点。试跑和 **测试节点** 都会实际执行节点。AI 节点会请求模型服务，HTTP 节点会向配置的地址发请求，都可能产生费用。第一次用短文本，流程里先不加外部写入节点。

1. **准备运行环境。** 在 **设置 → AI 助手** 配置可用的 Runtime。在普通会话收到回复后，回到 Loop 画布。
2. **摆好节点和连线。** 在画布左侧添加 **手动触发**、**AI 智能体任务**、**人工审批**、**输出**。连起前三个节点，将 **人工审批** 的 **通过** 出口接到 **输出**，**拒绝** 出口留空。
3. **给 AI 节点一条样本。** 选中 **AI 智能体任务**，在右侧选模型，在 **指令** 中填入一小段记录。示例输入为「周一录入样本表，周二统一单位，周三复核缺失项。把这三天的工作各写成一条摘要。」需要单独试跑时，对该 AI 节点点 **测试节点**，看到三条摘要后再跑整条流程。测试前会保存 Loop。
4. **设置人工审批。** 选中 **人工审批**，填写标题、说明和超时。这个例子的通过条件是三天的工作都写到了，内容与原记录相符。
5. **运行并作决定。** 点 **运行一次**，按界面确认。流程停在人工审批时，在卡片或运行抽屉打开带审批标题和 **通过／拒绝** 按钮的请求，阅读上游摘要。符合条件时点 **通过**。等待状态结束，**输出** 节点接到摘要，完成后运行标为 **成功**。摘要有遗漏时点 **拒绝**，**输出** 不会执行。
6. **找到本次结果。** 在 **运行日志** 打开 **输出**，可看到三条摘要。在 **运行历史** 打开本次记录，按需从 **审计报告** 查看各节点的输入、输出与耗时。用同一方式跑通一条代表性样本后，再批量执行。

## 能做什么

| 任务 | 配置位置 |
| --- | --- |
| 让 AI 生成内容或执行任务 | 加 **LLM 生成** 或 **AI 智能体任务**，填输入和输出要求。 |
| 按数据走不同步骤 | 加 **条件判断**、多路分支、合并、过滤或循环，检查每个引用来自哪个上游节点。 |
| 请求外部系统 | 加 **HTTP 请求**，确认网络、目标和权限。需要人工放行时，在请求前接 **人工审批**。 |
| 复用已有步骤 | 加子流程，选另一条 Loop，再核对输入。 |
| 自动启动 | 整条试跑结束后打开 **启用**，按需配置定时或 Webhook、启用 **AI 可调用**，或设置 Agent hook。计划和本地 Webhook 由应用进程触发，使用时应用需保持运行。 |

## 保存位置与操作影响

- 开始前核对工作目录、输入引用、失败处理、超时和输出路径。需要长期保留的结果，写到约定的工作区路径。重跑前先看已写入的文件和已提交的请求。
- 停止运行或决定审批时，按界面确认。需要 Secret 的节点在重跑时须能取得凭据，运行记录会隐藏 Secret 原值。
- 应用重启后，暂停在人工审批的那次运行需要重新发起。先在 **运行历史** 找到上次已完成的节点。若已经写文件或提交请求，先用保存的输出为起点，另建只包含后续步骤的 Loop，再点 **运行一次**。本页的纯文本示例可直接从 **手动触发** 重新运行。
- 随机性未固定时，复跑差异会标为不可判定。要做可复现对照，先固定随机性再比较结果。
