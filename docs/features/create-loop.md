# Create Loop（多步流程）

Create Loop 用于把一次任务拆成可检查的多个步骤。它位于会话执行之上：AI 节点负责生成或决策，条件与数据处理节点控制走向，HTTP 节点连接外部系统，子流程复用另一条 Loop，人工审批决定关键动作是否放行。功能状态表将本插件列为**已验证**。

## 打开方式

- 入口：工作台顶部 **创建 Loop**；在画布中编辑节点，右侧面板显示当前 Loop 的设置。
- 作用对象：当前工作区中的一条 Loop；定义与运行记录保存在本机领域状态。
- 前提：AI 节点需要可用的 Runtime 与模型；HTTP 节点需要网络；计划与本地 Webhook 由应用进程触发，应用需保持运行。可由手动 **运行一次**、定时触发、Webhook 触发或 Agent hook 启动。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 串起多步任务 | 从左侧节点面板添加 **AI 智能体任务**、**LLM 生成**、**条件判断**、**HTTP 请求**、人工审批和子流程等节点并连线 | 一条可保存的 Loop |
| 让流程按数据分支 | 用条件判断、多路分支、合并、过滤、循环等节点组织输入输出 | 明确的节点间数据流 |
| 先验证再上线 | 用 **测试节点** 配模拟上游输入单跑，再用 **运行一次** 跑整条 | 节点结果与运行日志 |
| 在关键处停下 | 加入 **人工审批** 节点，设置标题、说明与超时，在卡片或运行抽屉 **通过/拒绝** | 受控放行 |
| 自动触发 | 配置定时触发、Webhook 触发或 Agent hook | 计划、外部或事件触发 |

## 典型流程

1. 在顶部打开 **创建 Loop**，命名并确认工作目录；AI、图片和代码节点都会使用该目录。
2. 添加触发节点和任务节点，按执行顺序连线；为每个节点写清输入引用、失败处理和超时。
3. 先用 **测试节点** 加模拟上游输入验证单个节点；测试前会先保存当前 Loop。
4. 点击 **运行一次**，在 **运行日志**、**运行历史** 和 **审计报告** 中检查每个节点的输入、输出、耗时与错误。
5. 验证通过后再打开 **启用** 开关，按需开启 **AI 可调用**、配置定时或 Webhook，并在关键步骤前保留人工审批。

## 输入、输出与权限

- 读取：工作区文件、上游节点输出、Loop 定义、运行历史与审批状态。
- 写入：Loop 定义保存在本机领域状态；节点可写入工作区；每次运行保存运行 Manifest 与逐节点回执，并提供审计报告。
- 审批或外部影响：启动整条流程、停止运行和处理审批都按外部写入治理并要求确认；HTTP 与 AI 节点会产生真实请求和费用。
- 不会做什么：不把 Secret 的原始值写入运行记录；不在应用重启后恢复暂停中的审批；不自动替人批准。

## 已知限制

- **人工审批的暂停状态保存在内存中，应用重启会丢失该次运行**；重要流程应让节点可重复执行，并保留幂等标识。
- 计划与 Webhook 依赖应用进程运行；应用关闭时不会触发。
- Secret 变量只保存槽位与指纹；需要 Secret 且没有安全复跑解析时，执行会阻断，不会用空值继续。
- 单节点测试只证明该节点，不等于整条流程通过；测试也会真实执行节点逻辑。
- 随机性未固定时，复跑差异会被标为不可判定，不能直接当作复现失败。
