# Create Loop（多步流程）

Create Loop 用于把一次任务拆成可检查的多个步骤。它位于会话执行之上：AI 节点负责生成或决策，条件与数据处理节点控制走向，HTTP 节点连接外部系统，子流程复用另一条 Loop，人工审批决定关键动作是否放行。使用前先确认所选节点需要的模型、网络和工具可用，并在当前环境跑通整条流程。

## 打开方式

- 入口：右侧工具栏（未显示时展开 **更多工具**）的 **创建 Loop**；在画布中编辑节点，右侧面板显示当前 Loop 的设置。
- 作用对象：当前工作区中的一条 Loop；定义与运行记录保存在本机。
- 前提：AI 节点需要可用的 Runtime 与模型；HTTP 节点需要网络；计划与本地 Webhook 由应用进程触发，应用需保持运行。可由手动 **运行一次**、定时触发、Webhook 触发或 Agent hook 启动。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 串起多步任务 | 从左侧节点面板添加 **AI 智能体任务**、**LLM 生成**、**条件判断**、**HTTP 请求**、人工审批和子流程等节点并连线 | 一条可保存的 Loop |
| 让流程按数据分支 | 用条件判断、多路分支、合并、过滤、循环等节点组织输入输出 | 明确的节点间数据流 |
| 先验证再上线 | 用 **测试节点** 配模拟上游输入单跑，再用 **运行一次** 跑整条 | 节点结果与运行日志 |
| 在关键处停下 | 加入 **人工审批** 节点，设置标题、说明与超时，在卡片或运行抽屉 **通过/拒绝** | 受控放行 |
| 自动触发 | 配置定时触发、Webhook 触发或 Agent hook | 计划、外部或事件触发 |

## 典型流程

1. 在右侧工具栏或 **更多工具** 打开 **创建 Loop**，命名并确认工作目录；AI、图片和代码节点都会使用该目录。
2. 添加触发节点和任务节点，按执行顺序连线；为每个节点写清输入引用、失败处理和超时。
3. 先用 **测试节点** 加模拟上游输入验证单个节点；测试前会先保存当前 Loop。
4. 点击 **运行一次**，在 **运行日志**、**运行历史** 和 **审计报告** 中检查每个节点的输入、输出、耗时与错误。
5. 验证通过后再打开 **启用** 开关，按需开启 **AI 可调用**、配置定时或 Webhook，并在关键步骤前保留人工审批。

## 保存位置与操作影响

- Loop 定义与运行历史保存在本机。运行日志与审计报告可查看每一步的输入、输出和结果；重要流程还应把需要保留的结果保存到约定位置。
- 节点可能读取或写入工作区文件，也可能使用上游节点的输出。运行前检查工作目录与输出路径，重跑前核对已有文件和已完成的提交，避免重复操作。
- 启动整条流程、停止运行和处理审批都需要确认。HTTP 与 AI 节点会发出真实请求，并可能产生费用；**测试节点**也会执行实际操作。
- Secret 的原始值不会写入运行记录。人工审批需要你选择通过或拒绝；应用重启后无法恢复暂停中的那次运行。

## 已知限制

- **应用重启会丢失人工审批暂停中的那次运行**；重新运行前查看各步骤已保存的输入、输出和结果，确认哪些操作已经完成，避免重复写入或提交。
- 计划与 Webhook 依赖应用进程运行；应用关闭时不会触发。
- 需要 Secret 的步骤在重新运行时必须能取得所需凭据；凭据不可用时会停止执行，需要先恢复配置。
- 单节点测试只证明该节点，不等于整条流程通过；测试也会真实执行节点逻辑。
- 随机性未固定时，复跑差异会被标为不可判定，不能直接当作复现失败。
