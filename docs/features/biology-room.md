# Biology Room

Biology Room 是面向生物学样本或实验资料的工作区对象：把一次查看、标注和交接所需的序列、结构、基因组轨道与注释放在同一个版本化房间里。它当前没有独立渲染面板，文件内容仍由文件预览呈现；房间负责组织资产、选区、视图状态与历史。

## 打开方式

- 入口：会话中由 Agent 调用 Biology Room 能力创建或打开；房间内的文件通过文件预览查看。
- 作用对象：当前工作区中的生物学文件与房间清单；路径必须是工作区相对路径。
- 前提：工作区可写；资产扩展名受支持；需要引用索引时，索引与源文件同在工作区。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 建立房间 | 指定标题，可选地附带首批资产 | 初始房间清单与修订号 1 |
| 从文件打开或创建 | 传入一个工作区文件；已存在包含该文件的房间时直接复用 | 新房间，或已有房间的清单 |
| 添加与管理资产 | 以当前修订号为基准，提交资产增删或当前资产切换 | 新修订号；资产指纹、格式、模态与就绪状态 |
| 记录选区与标注 | 保存序列、结构或基因组选区与视图状态，并绑定注释锚点 | 结构化选区、视图状态与按锚点保存的注释 |
| 刷新与回溯 | 刷新资产指纹；查看历史并恢复修订 | 更新后的修订号、孤儿注释标记、历史事件 |

## 典型流程

1. 先列出现有房间，确认是否已有包含目标文件的房间，避免重复创建。
2. 从文件打开或创建房间；核对返回的路径、格式、SHA-256 与索引指纹。
3. 以当前修订号为基准提交一组变更，先用试运行模式查看是否有改动与警告。
4. 应用变更后再次读取房间，核对修订号、资产就绪状态和注释锚点。
5. 源文件变化后刷新房间；需要回退时先查看历史，再恢复旧修订生成新的修订号。

## 输入、输出与权限

- 读取：工作区内的 FASTA/GenBank、PDB/mmCIF、GFF3/BED/VCF 文件，可带 `.fai`、`.gzi`、`.tbi`、`.csi` 索引；单个资产最多 4 个索引。
- 写入：房间清单、修订快照与事件日志，存放在工作区 `.sciforge/biology/rooms/` 下的房间目录；源文件只读引用。
- 审批或外部影响：房间写操作只写工作区元数据且不触发审批；人工确认应放在试运行审查、级联移除资产与恢复旧修订之前。
- 不会做什么：不修改或删除源文件，不做比对、变异检测或结构计算，也不提供实时多人协同；移除资产只移除房间引用。

## 已知限制

- 支持范围窄于生命科学预览：不包含 FASTQ、GTF、组学矩阵、影像与光谱；gzip 只覆盖 FASTA、GFF、BED、VCF。
- 房间最多 128 个资产、2,000 条注释、100 MB 总资产；未建索引的单资产上限 25 MB。
- 房间没有独立界面；创建、变更和恢复都经会话中的 Agent 操作完成。
- 刷新后缺失或读取失败的资产会显式标记，失去锚点的注释会被标记为孤儿，需要人工确认后再处理。
- 应用变更会校验修订号，过期会被拒绝；历史按修订号保存且可能截断。
- 协作边界是共享同一份房间清单与版本历史，不是云端实时多人协同。
