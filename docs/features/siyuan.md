# 思源笔记

思源笔记把用户自备的远程思源服务接入工作台，作为阅读、编辑和归档科研记录的整页编辑器。它位于任务执行后的整理阶段，也可在任务中查阅笔记；SciForge 不自带内核，也不代替用户运行或管理该服务。

## 打开方式

- 入口：左侧栏的**思源笔记**，默认在会话右侧打开编辑器；可从页头移到左侧、底部或主区域，并调整大小。位置和大小会在本机保存。
- 作用对象：用户自己运行或订阅的思源服务，以及其中的笔记本与文档。
- 前提：一个可访问的 HTTP/HTTPS 思源地址；服务要求认证时，可在页面设置中填写 API Token，或使用环境变量 `SIYUAN_API_TOKEN`。SciForge 不启动、不随包分发思源内核。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 连接自己的思源 | 在页面**设置**中填写服务地址并保存；留空则使用安装默认地址 | 跨重启保留的编辑器会话 |
| 编辑与浏览笔记 | 在整页编辑器中直接使用思源界面 | 思源中的文档变更 |
| 搜索和读取已有笔记 | 让 Agent 按路径片段搜索，再按文档 ID 或路径读取 | 笔记位置与 Markdown 正文；长文会标明截断 |
| 自动归档任务总结 | 成功结束且产生最终回复的顶层 Agent 轮次会自动写入笔记本 | `SciForge 工作总结` 中的 Markdown 文档，含请求、最终回复、时间与轮次标识 |
| 让 Agent 写入指定文档 | 要求 Agent 把结果保存到思源，并提供标题、笔记本与路径 | 思源中的目标文档 |

## 典型流程

1. 先在思源服务中确认目标笔记本存在且可写；需要认证时准备好 API Token，在页面设置中保存或在启动环境中设置。
2. 从左侧栏打开思源笔记，在设置中填写服务地址；页面报错时用重试或打开设置修正。
3. 在编辑器中完成阅读或编辑；不要把不应离开本机的敏感内容放进远程服务。
4. 正常完成一轮 Agent 任务后，检查 `SciForge 工作总结` 下是否出现对应记录；服务暂时不可达时记录会排队重试。

## 保存位置与操作影响

- 阅读和编辑的内容来自已连接的思源服务。API Token 优先使用页面设置保存的值，否则使用环境变量；页面填写的 Token 保存在应用加密存储中。
- 自动归档保存到思源中的固定笔记本；让 Agent 写入文档时，应说明标题、笔记本与路径。
- 成功任务的归档会自动发送到已配置的思源服务，不会每次询问。使用前确认服务地址、可访问的笔记范围，以及哪些内容适合发送到该服务。
- 服务不可达时，待发归档保留在本机等待重试；正式笔记仍需成功写入思源服务。

## 已知限制

- 仅支持服务器模式：必须自备可访问的思源服务，地址必须是 HTTP/HTTPS。
- 内容空间目前只列出思源中已打开的笔记本；阅读、编辑与搜索文档请使用思源页面或 Agent 工具，内容空间不能上传下载文件。
- 自动归档只覆盖成功的顶层 Agent 轮次；中间进度、失败、取消和持续子轮次不归档，也不做第二次 AI 总结或声称任务已验证。
- 归档写入固定笔记本 `SciForge 工作总结` 和 `/SciForge` 路径，笔记本不存在时会创建；同一轮任务重试前会检查对应任务笔记是否已存在，避免重复创建。
- SciForge 不随包提供思源内核；本机使用也需要自行部署服务。
- 服务不可达或写入结果不确定时，待发记录保留在本机并在下次任务或启动时重试；无法确认的写入不会盲目重复。
