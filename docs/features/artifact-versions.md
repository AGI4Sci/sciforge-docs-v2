# 产物版本（Artifact Versions）

Artifact Versions 为工作区中的单个产物建立稳定身份，并把每次保存记录为不可变版本。它解决“同一张图、同一份数据改到第几版、能否回到某一版”的问题，位于分析产出之后、证据整理与交付之前；研究上下文仍由 [Research Checkpoints](./research-checkpoints.md) 记录，主张与来源关系由 [Evidence DAG](./evidence-dag.md) 负责。

## 打开方式

- 入口：工作台科研摘要的 **Artifacts** 区域列出最近产物；选择具体条目后，在右侧 **科研** 面板查看版本。
- 作用对象：当前工作区中的单个产物，例如图表、数据、日志或代码文件。
- 前提：Agent 或生产插件已把产物提交为版本，且会话绑定工作区。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 固定一次产出 | 让 Agent 或绘图等生产插件提交新版本 | 不可变版本与当前指针 |
| 大文件入库 | 通过分阶段上传（begin → append → seal，失败时 abort）提交字节 | 内容寻址快照 |
| 比较两个版本 | 在科研档案的 **版本** 区选择精确版本并比较 | 内容、元数据与依赖差异 |
| 回到旧版本 | 选择历史版本并恢复为新版本 | 新的当前版本，旧版本保留 |
| 打包交换 | 在科研档案中选择精确版本导出 Bundle，导入前先校验 | 可移植 bundle 与校验结果 |

## 典型流程

1. 在任务中生成图表或数据，确认文件位于当前工作区。
2. 让 Agent 提交产物；需要时补齐依赖与访问策略。
3. 在 **科研** 面板打开精确版本，核对内容摘要与依赖。
4. 修改后再次提交，比较新旧版本；需要时恢复为新版本。
5. 交付前在科研档案选择精确版本导出 Bundle，并在目标工作区校验后导入。

## 输入、输出与权限

- 读取：当前工作区的产物元数据、版本历史与快照字节；受限版本按访问策略过滤。
- 写入：版本索引、内容寻址对象与生命周期事件；恢复只新增版本，不改写历史。
- 审批或外部影响：Bundle 导出会写出 bundle 文件，导入会安装版本记录；从科研档案触发导出时，界面会先请求确认。
- 不会做什么：不判断科学结论，不生成主张与来源关系，也不在没有精确版本时回退到“最新版”。

## 已知限制

- 功能状态为 **部分可用**：入口已经注册，但只有任务实际提交过产物才会有内容；空面板不代表功能故障。
- 快照字节按内容寻址保存；引用型版本在读取时会重新校验工作区文件，移动、内容变化或缺失会反映为来源状态。
- 导出 Bundle 必须显式选择非空的产物或版本；闭包中有任一版本不可见或禁止导出时，整次导出失败；导入会拒绝不完整依赖、非线性历史、重复序号、循环引用或损坏对象。
- 分阶段上传按块传输，单块上限 4 MiB；未完成且已过期的阶段不能继续追加。
- 每个版本携带不可变访问策略；读取、比较、恢复和导入都会执行同一策略，受限版本不会因历史界面而放宽。
