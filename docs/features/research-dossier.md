# 科研档案（Research Dossier）

科研档案是面向阅读与交付的研究视图：它打开一个精确的产物版本或计算运行，再把各领域提供的只读记录组合成研究叙事、关键产物、复现状态与限制。它自身不保存记录、不持有当前指针，也不会用最新版本替代请求的精确记录；研究过程的记录由 [Research Checkpoints](./research-checkpoints.md) 负责，证据关系仍由 [Evidence DAG](./evidence-dag.md) 维护。

## 打开方式

- 入口：顶部工具栏 **科研**；右侧面板标题同为 **科研**；会话结果卡片的 **打开科研档案** 绑定精确版本。
- 作用对象：精确的产物版本或计算运行，而不是模糊的“最新结果”。
- 前提：已有研究检查点、精确产物版本或计算运行记录，且会话绑定工作区。

![SciForge 科研档案面板](/img/docs/guides/research-dossier.jpg)
*科研档案把研究叙事、版本位置、可信度摘要与需要关注的限制放在同一个阅读面。*

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 阅读一项研究记录 | 从精确版本或计算运行打开 | 概览、关键产物与可信度摘要 |
| 检查研究限制 | 查看 **需要关注的限制** 与 **溯源断点** | 可操作的限制清单 |
| 浏览历史版本 | 在 **版本** 区加载更早版本 | 版本列表与当前位置 |
| 比较或恢复 | 使用 **比较精确版本** 或 **恢复为新版本** | 差异摘要与新的当前版本 |
| 预览或导出 | 使用 **打开已校验预览** 或 **导出 Bundle V2** | 已校验预览与可移植 bundle |
| 管理自动记录 | 开启或停止自动记录，或导入此前聊天 | 策略修订号与 legacy 记录 |

## 典型流程

1. 完成一轮研究，在结果卡片点击 **打开科研档案**。
2. 核对精确目标与版本位置，必要时展开技术详情查看 Version ID 与摘要值。
3. 阅读概览、研究来源、声明文件、复现状态与限制。
4. 需要追溯或回退时比较精确版本或恢复为新版本，并检查所属领域的回执。
5. 交付前导出 Bundle V2，确认访问限制与未验证项已交代清楚。

## 输入、输出与权限

- 读取：产物版本、研究检查点、计算运行、证据与 Git 检查点等所属领域的精确记录。
- 写入：档案自身不写记录；恢复、导入与记录开关都委托给所属领域执行。
- 审批或外部影响：恢复与旧会话导入按所属领域的确认策略执行；Bundle 导出会写出工作区文件并请求确认。
- 不会做什么：不保存记录副本，不拥有当前指针，不在记录缺失或摘要不匹配时回退到 latest。

## 已知限制

- 功能状态为 **部分可用**：入口已经注册，但内容质量取决于任务是否产生检查点、产物版本和证据记录。
- 档案本身不存储记录；某个所属领域不可用时，只降级对应区块，其余已校验内容仍可阅读。
- 精确身份或摘要不匹配会 fail closed，不会替换成来源、当前版本或最新版本。
- 导入的旧会话会永久标记为 legacy / incomplete，并保留阻断性溯源断点。
- 空区块和不适用的计算、证据或审查区块会被省略；需要完整关系图时回到 Evidence DAG。
