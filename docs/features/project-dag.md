# Project DAG

Project DAG 把同一项目内多个会话的已提交 Evidence 快照，按目标、范围与策略编译为项目级不可变快照。它回答“整个项目目前知道什么、哪些结论仍待审查”，不读取原始聊天，也不接受未提交的来源图；会话内的主张与证据关系仍以 [Evidence DAG](./evidence-dag.md) 为唯一事实层。

## 打开方式

- 入口：右侧面板 **项目 DAG**；从项目、Goal 或 Snapshot 资源导航可打开对应视图。
- 作用对象：当前工作区对应的项目及其已提交 Evidence 快照。
- 前提：项目内至少有一个已提交 Evidence 快照，且 Evidence 与 Project 服务均可用。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 查看项目全局图 | 打开面板，读取最近的已提交 Project 快照 | 项目级主张、发现与审查状态 |
| 设定项目目标 | 在 **项目目标** 填写标题与描述，点击 **保存目标** | 新的 Goal 版本 |
| 汇总新证据 | 点击 **立即更新**，等待任务提交 | 新的 Project 快照与回执 |
| 查看待关注项 | 查看需要关注的数量、审计状态与审查包 | 待处理清单 |
| 回到会话证据 | 点击 **打开某会话的 Evidence DAG** | 对应会话的证据图 |
| 查看 Claim 溯源 | 选择 Claim，查看最强溯源路径、来源、L0–L4 与断点 | 跨层溯源详情与相关决策 |

## 典型流程

1. 在多个会话中完成分析，并分别在 Evidence DAG 提交快照。
2. 打开项目 DAG，填写项目目标并保存。
3. 点击 **立即更新**，确认回执进入排队、执行并最终提交。
4. 检查需要关注项与关键 Claim，必要时跳回来源会话核对。
5. 对受限来源只读取脱敏后的路径与断点，不尝试绕过访问策略。

## 输入、输出与权限

- 读取：已提交 Evidence 快照、项目图、Claim、审计记录与决策记录。
- 写入：项目更新任务、Goal 版本与不可变 Project 快照；审计只写独立侧链。
- 审批或外部影响：面板操作限于本地项目记录；任何发布或外发仍需 Runtime 授权，项目策略不能替代它。
- 不会做什么：不读取原始聊天，不接受未提交的来源图，不从审计页直接修改图，也不缓存 Evidence 快照内容。

## 已知限制

- 当前实现范围只消费已提交的 Evidence 快照；上游提交只标记项目需要刷新，不会自动逐条编译。
- Project 视图关闭时不会预先编译；需要新视图时要显式更新，并等待持久化回执。
- 新快照提交后，旧快照上的排队、运行、已完成或失败审计会标记为过期，旧 Finding 不会覆盖新图。
- 任一环节受访问策略限制时，溯源路径会脱敏并 fail closed，只保留不可逆哈希、存在性、等级与断点。
- 审计是 fail-open 的只读侧链，审计失败不会把已提交的 Project 任务改成失败，也不能直接改图。
