# 研究检查点（Research Checkpoints）

Research Checkpoints 自动保存已接受并完成的聊天回合，记录研究摘要、修改原因、来源以及相关文件和 Git 引用，帮助你了解当时做了什么、依据是什么、下一次从哪里继续。记录中也会提示哪些操作缺少完整记录。

## 打开方式

- 入口：会话结果卡片中的 **本轮科研记录**；卡片提供 **打开科研档案**。
- 作用对象：当前会话中已完成的聊天回合及其绑定的工作区。
- 前提：自动记录默认开启，会话绑定工作区；第一轮完成后生成首个版本。

## 查看和继续研究

1. 在绑定工作区的会话中完成一轮研究，等待结果卡片显示记录已保存。
2. 查看标题、修改原因、输入与输出，核对来源和相关文件是否对应本轮工作。
3. 查看是否有分析无法重新运行，或结果无法追查到来源的提示。操作记录不完整时，补充实际命令、环境和输出，便于以后复查。
4. 在 **精确产物版本** 中选择输出并点击 **打开**，检查所引用的实际版本。
5. 点击 **打开科研档案** 阅读完整记录；需要接续历史记录时，可选择它并恢复为新版本，保留原有历史。

## 保存内容

检查点保存的是摘要和引用。实际文件内容与产物版本需要另外保存和核对，参见 [Artifact Versions](./artifact-versions.md)；整个工作区的 Git 状态见 [Git Checkpoints](./git-checkpoints.md)。仅有研究摘要，并不意味着所有结果文件都已留存。

保存时会根据本轮对话、工具结果、工作区文件变化以及相关产物、计算和 Git 记录，新增一个检查点版本，已有版本会保留。尚无法确认记录应关联到哪里时，会显示待处理，应先核对再继续。

## 管理自动记录

在科研档案中使用 **开启自动记录** 或 **停止自动记录**。停止期间完成的回合不会被事后自动补录。遇到版本冲突时，可以基于当前版本重新保存，或放弃本轮记录。

导入旧会话、处理冲突和恢复为新版本需要确认。导入旧会话只保留聊天内容；系统仍会提示历史记录不完整、部分结果无法追查到来源。导入本身不会补齐当时缺失的研究过程。

## 使用提示

- 只记录已接受且完成的聊天回合；尚未完成的任务需要等待完成后再检查。
- 通过终端、编辑器等途径完成的操作，可能只记录到发生了哪些变化，未完整记录这些结果是怎样生成的。请结合实际文件与运行记录核对。
- 新检查点默认仅工作区可见且禁止导出。分享前应检查访问权限和记录内容。
- 记录会对部分叙述、网址和类似凭据的查询参数脱敏，但仍应人工检查敏感信息。
