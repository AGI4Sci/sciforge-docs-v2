# 协作使用说明

负责人写清需求并确认分工，成员接单后在自己的 SciForge 中执行任务、审阅草稿并提交，最后由负责人采纳成果。需要接力的任务使用上游已采纳的文件。

## 打开协作项目

1. 展开左侧边栏，在底部账户区域完成[云端登录和设备连接](./identity-access.md)。
2. 在侧边栏的协作区域打开项目、**我的工作**或**收件箱**。若看不到项目树，先展开侧边栏。
3. 先在普通会话中确认 Runtime 和模型能够响应，再开始协作任务。

每位成员使用自己的云端账号。项目需求、讨论、结果说明和提交文件会进入协作服务；普通本地工作区不会整目录自动同步。不要在这些内容中填写模型密钥或登录凭据。

选中项目后，顶部有五个标签页：

| 标签页 | 用途 |
| --- | --- |
| **看板** | 查看任务、接单、派发、审阅与采纳进度 |
| **成员** | 查看项目成员，按当前角色邀请或管理成员 |
| **需求** | 编辑目标、输入、工作模块与验收标准，确认需求 |
| **共享文件** | 查看共享资料、已封存的任务交付与项目成果 |
| **项目信息** | 查看项目说明、状态及可用的管理操作 |

## 1. 负责人准备并确认需求

1. 在协作项目区域使用 **＋** 创建项目，填写名称。
2. 打开 **需求**，编辑 **目标与交付** 和 **输入与边界**，写明数据来源、最终文件、验收方式和不能执行的操作。
3. 点击 **保存需求**，等待工作模块补全。失败时先看提示，检查模型配置，再使用 **重新补全**。
4. 检查每个模块的目标、输入、产出、依赖及验收标准，确认无误后点击 **确认需求**。
5. 在 **成员** 中邀请成员；受邀者从收件箱或项目邀请提示进入，阅读需求后接受邀请。

例如：“B 计算样本总计数并提交报告；C 使用 B 已采纳的报告继续比较。报告须包含方法、校验结果和限制。”同时提供成员真正可以读取的输入。

## 2. 检查派单与阻塞原因

负责人在看板打开任务，检查执行人和上游依赖。可按任务当前状态选择成员后 **派发任务**、**重新派发**，或对尚未接受的派单 **改派**、**撤回派单**。

有依赖的模块需要等待上游成果被采纳。此时界面保留派发入口并显示原因，按钮不可用；应先完成上游评审。需求确认后若任务仍待分配，或派单失败且没有可用成员，负责人需要按提示选择执行人或处理待办。不要把待派发任务当作已经开始运行。

## 3. 成员决定是否接单

成员可从 **收件箱、我的工作、看板任务卡或任务详情**查看收到的派单。先读目标、文件要求、依赖与有效期，再选择：

| 操作 | 结果 |
| --- | --- |
| **接受任务** | 确认承担任务；本机 Runtime 就绪后执行，未就绪时按提示恢复 |
| **忽略** | 处理当前派单，任务会从本人的相关列表移出；它不是关闭提示条 |
| **拒绝** | 明确拒绝当前派单，由负责人根据项目状态重新安排 |

以实际可用按钮为准；已失效或已处理的派单不能重复接受。只关闭看板上的接单提醒，不会替你执行“忽略”。接受后，通过任务会话查看运行进度和工具调用。

## 4. 处理 Agent 提问与动作确认

任务需要补充信息时，指定成员在任务详情中回答。若请求涉及修改文件、向外部系统写入或删除等动作，先阅读具体动作、影响范围、请求版本与有效期，填写决定说明，再点击 **批准该动作** 或 **拒绝该动作**。

只有指定成员可以决定，过期请求需等待更新。提交决定后查看回执与后续任务进度；动作是否完成要看实际执行结果。普通讨论消息不会代替动作批准。

## 5. 成员审阅草稿并提交

1. 执行结束后打开交付草稿，预览必交文件并检查内容。
2. 编辑 **结果说明**，写清实际完成内容、检查结果和限制。
3. 需要补充材料时点击 **添加资料**：从 **任务文件**选择本次产物，或使用 **从本机上传**添加材料。附加资料不会替换必交文件。
4. 需要 AI 修改时，通过 **让 AI 修改**进入任务会话。
5. 核对文件清单，点击 **提交**，在确认窗口检查版本、说明和文件，再确认提交。

提交期间等待设备验证、签署与文件上传的明确结果。若出现系统安全存储授权，由本人处理。成功后会形成带版本号的**交付快照**，等待负责人评审；这一版不能原地修改，返修会形成新版。

一次交付最多 20 个文件、合计不超过 200 MiB；附加文件单个不超过 100 MiB。必交文件还可能有任务自己的格式与大小要求，按提交窗口提示处理。

## 6. 负责人评审，交给下游继续

在看板打开待确认任务，预览本版文件，对照验收标准阅读结果说明。需要补充时使用 **要求修改**并填写具体意见；成员修改、复核后提交新版。满足要求后点击 **采纳**，任务进入已完成状态。

历史版本保留旧快照，评审时核对当前版本。上游被采纳后，下游任务才可继续派单；下游执行使用已采纳版本的文件。

## 7. 查看共享文件与结项

**共享文件**按来源与版本列出项目文件，可预览已提交内容。这里的 **上传文件** 当前不可用，并显示原因。要随任务提交材料，请回到交付草稿的 **添加资料**；不要在共享文件页等待上传成功。

全部模块被采纳后，负责人检查成果与限制，再使用 **结项**入口确认项目完成，等待签署和服务端结果。

## 看板状态速查

| 列 | 含义 | 下一步 |
| --- | --- | --- |
| 收集箱 | 模块尚未派出，可能等待依赖或人工分配 | 负责人查看阻塞原因与执行人 |
| 待开始 | 已派单，等待成员接受 | 成员阅读后接受、忽略或拒绝 |
| 进行中 | 执行、等待人工回答或成员审阅草稿 | 查看任务详情，按当前请求处理 |
| 待确认 | 交付已提交 | 负责人评审、要求修改或采纳 |
| 已完成 | 模块成果已采纳 | 全部模块完成后由负责人结项 |

网络中断、提交失败或签名错误时先保留草稿，检查登录与设备状态，恢复后核对是否已有提交记录，再按提示重试。
