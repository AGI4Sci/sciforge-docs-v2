# 协作使用说明

协作让一个负责人和多位成员共同完成项目：负责人写需求，AI 补全工作模块，成员在自己的 SciForge 中接受任务、执行并审阅草稿，负责人评审交付，下游使用已采纳的成果，最后结项。

第一次使用时，可以按本页走完一轮，再查看 [Pasilla 三人协作案例](../cases/pasilla-collaboration.md)，对照真实截图理解每一步的完成标志。

## 使用前准备

1. 安装管理员提供的、与协作服务匹配的 SciForge 桌面版本。
2. 按[身份与登录](./identity-access.md)完成 Cloud 登录和当前设备连接。打开左侧的**协作**，确认状态为**云端已连接**；服务地址由管理员提供。
3. 负责人和执行任务的成员分别配置可用的 Runtime 与模型，先确认普通会话能够工作。参见 [Runtime 与模型](../getting-started/runtime-and-models.md)。
4. 准备目标、输入数据、输出要求和验收标准。每位成员使用自己的云端账号参与项目。

需求补全需要结构化输出。如果模型仅支持 JSON 对象，在**设置 → 模型访问 → 模型 API**中按渠道能力选择相应模式。Pasilla 案例使用 OpenAI Chat Completions 和**仅 JSON 对象**，这不是所有模型的固定配置。

## 角色与页面

| 角色 | 主要操作 |
| --- | --- |
| 负责人 | 创建项目、确认需求、邀请成员、调整分配、要求修改或采纳交付、结项 |
| 成员 | 接受任务、与本机 AI 对话、检查文件、编辑结果说明、确认提交 |
| Coordinator | 在负责人一侧辅助补全需求和组织工作模块；交付采纳由负责人决定 |
| 成员本机 AI | 按任务说明执行并生成草稿；草稿需要成员审阅提交 |

左侧**我的工作**用于查找本人任务，**收件箱**用于处理邀请和派单。选中项目后，可以在**看板、需求、文件、项目设置**之间切换。

## 1. 负责人创建项目并写需求

1. 打开**协作**，点击项目区域旁的 **＋**，按界面填写项目名称并创建。
2. 进入项目的**需求**页，编辑**目标与交付**和**输入与边界**。
3. 在目标中写明最终文件、分工和验收方式；在输入中写明可用数据、来源以及分析范围。
4. 点击**保存需求**。保存会自动启动工作模块补全，等待完成后再检查结果。

例如：“B 计算样本总计数并出报告；C 基于 B 已采纳的报告继续比较；报告需包含方法、校验结果和分析限制。”同时在需求中提供任务实际可读取的输入。

**完成标志**：出现生成的工作模块及任务说明，显示待确认状态。补全失败时先查看提示，调整后可使用**重新补全**。

![需求页生成工作模块，负责人可以检查后点击确认需求](/img/docs/collaboration/requirements-ready.png)
*图 1：补全后的需求页。下游模块明确依赖上游已采纳的结果。*

## 2. 负责人确认需求、邀请成员并检查分配

1. 检查各模块的任务说明、输入、产出和依赖。有问题时先编辑需求并重新补全。
2. 点击**确认需求**，将当前版本确认为项目基线。
3. 通过项目的成员管理入口邀请成员；被邀请者在各自收件箱中接受邀请。
4. 回到看板检查任务卡上的负责人。需要调整时，打开任务卡使用改派入口，选择目标成员。

**完成标志**：看板出现任务卡；已派出的任务等待成员接受，有依赖的任务显示等待上游采纳。负责人可根据团队分工调整任务分配。

## 3. 成员接受任务并让本机 AI 执行

1. 打开自己的**收件箱**或**我的工作**，进入收到的任务。
2. 阅读目标、输入、交付要求及依赖，确认后点击接受任务。
3. 接受后本机 AI 开始执行。通过任务中的会话入口查看进度、工具调用和生成文件。
4. 需要补充要求时，使用草稿中的**让 AI 修改**进入该任务会话；AI 提问时在相应入口回答。

**完成标志**：执行结束后出现可审阅的交付草稿和文件。AI 会话结束并不等于交付已提交，此时还需要成员检查和确认。

## 4. 成员检查草稿、添加资料并提交

1. 点击文件的**预览**，检查内容和计算是否符合任务说明。
2. 编辑**结果说明**，说明实际完成内容、检查和限制。它会随本版交付保存。
3. 点击**添加资料**，从**任务文件**选择本次执行产生的文件，或通过**从本机上传**选择自己的文件。
4. 核对提交清单。示例中的 AI README 是必交项，成员另加了一份说明；附加资料不会替换必交文件。
5. 点击**提交**，在确认窗口再次检查版本、说明和文件，然后确认。

![成员交付草稿包含结果说明、AI README 和成员自行添加的说明文件](/img/docs/collaboration/delivery-draft.png)
*图 2：第 1 版草稿包含两项文件，提交前仍可编辑说明和调整附加资料。*

提交期间会显示当前阶段，例如设备验证与签署、准备提交或上传文件。如果弹出系统钥匙串授权，由本人处理，再等待应用返回结果。

![提交窗口显示正在上传交付文件及本版文件清单](/img/docs/collaboration/delivery-submitting.png)
*图 3：正在上传仍属于提交过程，应等待明确的封存结果。*

**完成标志**：草稿变成带版本号的**交付快照**，显示已提交、等待负责人确认。封存后的这一版不可原地修改；返修会形成新版本。

:::note[文件限制]

一次交付最多包含 20 个文件，合计不超过 200 MiB，附加文件单个不超过 100 MiB。请同时遵守任务对必交文件的要求；本案例中的 AI README 报告上限为 1 MiB。

:::

## 5. 负责人预览、要求修改或采纳

1. 在看板打开**待确认**的任务，预览已提交版本中的文件，阅读结果说明。
2. 对照验收标准检查。有问题时点击**要求修改**，填写具体意见并发送，例如：“补充每样本零计数比例，并列出 CPM 列和校验。”
3. 成员收到意见后修改，重新审阅并提交新版。
4. 负责人再预览这一版，确认满足要求后点击**采纳**。

![负责人在已提交交付下填写具体返修意见并发送返修要求](/img/docs/collaboration/revision-request.png)
*图 4：正式返修通过“要求修改”发送；任务讨论框用于沟通。*

**完成标志**：采纳后模块移入**已完成**，项目已采纳计数增加。成员提交成功后仍需等待负责人评审。

## 6. 查看历史版本与下游接力

在任务交付区域展开**历史版本**，可查看前几版快照。返修不会覆盖旧版，评审时应核对当前版本号。

![第 2 版交付快照下方保留第 1 版历史记录](/img/docs/collaboration/delivery-history.png)
*图 5：成员已提交第 2 版，第 1 版仍可展开查看。*

上游被采纳后，有依赖的下游任务才会继续派单。下游成员接受并执行时，系统把上游已采纳版本的文件作为输入，无需人员之间手动复制。Pasilla 案例展示了 C 使用 B 第 2 版报告和成员说明的过程。

## 7. 负责人结项

1. 检查全部模块已采纳，例如显示**已采纳 2/2**。
2. 点击项目的**结项**入口，填写实际完成范围、成果与限制。
3. 确认结项，等待设备签署和云端结果。

**完成标志**：项目标题旁显示**已完成**，任务卡均处于已完成列。全部模块已采纳后，仍需负责人完成结项操作。

![项目显示已完成和已采纳 2/2，两张任务卡都在已完成列](/img/docs/collaboration/project-completed.png)
*图 6：项目最终完成状态。*

## 看板状态速查

| 列 | 含义 | 下一步 |
| --- | --- | --- |
| 收集箱 | 尚未派出的模块，可能等待上游采纳 | 负责人检查分配与依赖 |
| 待开始 | 已分配、等待成员接受 | 成员阅读并接受任务 |
| 进行中 | AI 执行中，或成员正在审阅、修改草稿 | 成员审阅后提交 |
| 待确认 | 交付已封存，等待评审 | 负责人采纳或要求修改 |
| 已完成 | 模块交付已被采纳 | 全部完成后由负责人结项 |

## 遇到问题时

| 现象 | 建议处理 |
| --- | --- |
| 需求补全失败 | 查看错误，检查模型、协议和结构化输出配置，调整后点击重新补全 |
| AI 执行失败或中断 | 返回任务草稿查看错误，按提示重新执行或继续编辑草稿；重新执行按所用模型渠道计费 |
| 提交或结项提示设备签名错误 | 保留内容，检查登录、设备连接和系统授权；核对当前提交记录后按提示重试，仍报错时联系管理员 |
| 网络中断或正在重连 | 保留草稿，连接恢复后核对任务状态，避免重复提交 |

## 数据与文件说明

- 需求、成员关系、任务、讨论、提交的结果说明和交付文件会进入协作云服务。普通本地工作区不会因此整目录自动同步。
- 调用远程模型 API 时，任务上下文和模型需要的内容可能发送给配置的模型服务商。模型密钥由本机配置管理，请勿填入需求、讨论或交付文件。
- 任务要求的必交文件需要保留；其他材料可通过**添加资料**补充，并随交付一起提交。
