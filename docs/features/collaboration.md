# 协作使用说明

负责人在 **需求** 定交付标准，在 **看板** 派单和评审。执行成员在任务详情补齐必交文件、提交或返修。下游成员在自己的任务中使用上游已采纳的版本。

## 打开协作项目

1. 展开左侧边栏，在底部账户区完成[云端登录和设备连接](./identity-access.md)。每位成员用自己的账号。
2. 从侧边栏协作区打开项目、**我的工作**或**收件箱**。进入项目后，顶部显示项目名称，**看板**列出该项目的任务。
3. 接单前可在普通会话发一条简短消息。收到回复后，再打开派单。

| 项目标签 | 去这里做什么 |
| --- | --- |
| **看板** | 找任务，查看派单、交付和采纳状态 |
| **成员** | 按角色权限邀请或管理成员 |
| **需求** | 编辑并确认目标、输入、工作模块和验收标准 |
| **共享文件** | 查看共享资料、封存交付和项目成果 |
| **项目信息** | 查看项目说明和状态，使用可用的管理操作 |

需求、项目讨论、结果说明和提交文件会发往协作服务。普通本地工作区仍保存在本机。请通过各服务的凭据设置保存密钥。

## 1. 负责人准备并确认需求

1. 在协作项目区域点 **＋**，填写项目名称。
2. 打开 **需求**，在 **目标与交付**、**输入与边界** 写明数据来源、文件名、验收方式及允许的操作范围。给成员提供可访问的输入。
3. 点 **保存需求**。补全后 **工作模块** 与 **验收标准** 会列出每个模块的输入、必交文件、前序依赖及验收要求，阅读无误后点 **确认需求**。若补全失败，按页面报错恢复模型或协作连接，再点 **AI 补全** 重试。
4. 在 **成员** 发出邀请。请受邀成员从 **收件箱** 或项目邀请提示打开需求，并点 **接受邀请**。接受后，受邀成员会列在 **成员** 页。

例如，让 B 提交样本总计数报告，列出方法和核对结果。设置 C 的任务依赖 B，输入指定为 B 经负责人采纳的报告。

![协作需求历史页面](/img/docs/collaboration/requirements-ready.png)
*确认需求前，检查模块及上游依赖。*

## 2. 检查派单与阻塞原因

负责人在 **看板** 打开任务，查看执行人与依赖。有可用执行人且上游已采纳时，选择成员后点 **派发任务**，任务卡进入 **待开始**，并显示被派单的成员。派发失败后，按任务详情的提示补齐条件，再点 **重新派发**。派单尚未被接受时，可用 **改派** 或 **撤回派单**。

| 任务详情显示什么 | 负责人接下来做什么 |
| --- | --- |
| 等上游采纳，派发按钮不可用 | 打开上游任务，评审最新交付。采纳后再回来看下游任务。 |
| 待分配，或派单失败且缺少可用成员 | 选择执行人，或按待办处理成员分配。派出后，任务卡显示执行人及 **待开始**。 |

## 3. 成员决定是否接单

从 **收件箱**、**我的工作**、**看板**任务卡或任务详情打开派单。先读目标、必交文件、依赖与有效期，再选界面提供的操作。

| 操作 | 你会看到什么 |
| --- | --- |
| **接受任务** | 任务由你承担。Runtime 就绪后可在任务会话查看进度，未就绪时先按提示恢复。 |
| **忽略** | 当前派单从与你相关的列表移出。 |
| **拒绝** | 当前派单被拒绝，由负责人重新安排。 |

只想收起提醒时，关闭看板提示。派单已失效时，请负责人更新派单。

## 4. 处理 Agent 提问与动作确认

- **回答问题**。任务缺数据或需要确认口径时，由收到请求的指定成员打开任务详情，填写回答，再回任务会话查看后续进度。
- **决定是否批准动作**。从任务详情打开请求。先看要改哪个文件、会把数据发到哪里，再看请求版本和有效期。写一句理由，点 **批准该动作** 或 **拒绝该动作**。请求过期时，等新请求。批准后回任务会话看动作的执行结果。

讨论中的消息可用于补充背景。提交授权决定请使用请求里的按钮。

## 5. 成员审阅草稿并提交

1. 打开任务详情的交付草稿，预览必交文件。若 **提交** 不可用，先看提交区指出缺的是哪份文件。在提供 **选择必交文件** 的客户端，选择任务产物或从本机上传，再点 **用作必交文件**。文件会出现在必交清单，可从清单点 **预览** 打开。
2. 在 **结果说明** 写清做了什么、检查结果和适用范围。需要让助手返工时，点 **与 AI 一起完成**，在任务会话修改后回来看草稿。
3. 另附说明时点 **添加资料**，从 **任务文件** 选产物，或用 **从本机上传**。单次最多 20 个文件（包含必交文件）、合计 200 MiB，附加文件单个最多 100 MiB。必交文件还需满足任务声明的格式和大小。
4. 点 **提交**。在「提交第几版」的窗口里查看版本号、结果说明和文件，再点一次 **提交**。上传和签署完成后，交付区显示刚提交的版本，看板中的任务进入 **待确认**。若系统弹出安全存储提示，由执行成员本人处理。

![成员交付草稿](/img/docs/collaboration/delivery-draft.png)
*在交付草稿填写结果说明。必交文件和附加资料各有一份清单。*

![提交交付的进度](/img/docs/collaboration/delivery-submitting.png)
*提交时显示设备验证、签署和文件上传进度。*

## 6. 负责人评审，交给下游继续

1. **负责人看最新提交。** 在 **看板 → 待确认** 打开任务。先读交付区顶部这一版的 **结果说明**，再点各文件旁的 **预览**，对照需求里的验收标准。
2. **需要返修时写清改哪一处。** 点 **要求返修**，填写意见，再点 **发送返修要求**。执行成员读完意见，更新文件和说明，再提交新版本。负责人回交付区打开顶部的新提交。原版可用 **历史版本** 查看。
3. **验收通过后采纳。** 点 **采纳交付**。任务进入 **已完成**，交付区显示 **已采纳** 和本次版本号。
4. **下游用已采纳版本。** 上游采纳后，负责人派发下游任务。下游成员点 **接受任务**，进入任务会话。在右侧 **文件** 面板打开任务工作目录，读取放在这里的已采纳文件。

![负责人填写返修意见](/img/docs/collaboration/revision-request.png)
*负责人按本次交付填写具体返修意见。*

![交付历史版本记录](/img/docs/collaboration/delivery-history.png)
*交付历史列出各版提交。评审打开最新一版，下游任务使用已采纳的一版。*

## 7. 查看共享文件与结项

在 **共享文件** 按来源和版本查找并预览文件。要随任务提交自己的文件，从交付草稿点 **添加资料**。

全部模块均已采纳后，负责人点 **结项**。在弹窗填写 **结项总结**，然后点 **确认结项**。签署完成后，项目状态显示 **已完成**。

![协作项目结项状态](/img/docs/collaboration/project-completed.png)
*已采纳两项交付，项目显示已完成。*

## 看板状态速查

| 列 | 接下来由谁处理 |
| --- | --- |
| 收集箱 | 负责人查看上游依赖和执行人。 |
| 待开始 | 已派单，等指定成员响应。 |
| 进行中 | 执行成员查看进度、回答问题或审阅草稿。 |
| 待确认 | 交付已提交，等负责人评审。 |
| 已完成 | 成果已采纳。全部任务完成后，负责人可结项。 |

网络中断、提交失败或签名报错时，保留草稿，检查登录和设备状态。恢复后打开任务详情。交付区已显示本次提交时可直接等评审；仍只有草稿时，从任务详情重新 **提交**。
