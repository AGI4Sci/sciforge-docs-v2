# 科学计算（Scientific Compute）

科学计算提供一条本地、确定性的作业循环基线：提交、监控、结果收集与事件轨迹都在本机固定样例（fixture）中完成，用于验证科研计算的记录方式，而不是提交真实集群作业。它处在“准备真实计算”之前，真正的远程执行仍交给 Remote SSH 或终端。

## 打开方式

- 入口：会话中由 Agent 调用基线任务；当前没有独立的工作台面板。
- 作用对象：全局运行状态，不绑定某个工作区。
- 前提：无需调度器、集群账号或外部服务；需要可用的 Runtime 来发起调用。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 确认当前计算提供方 | 查询状态 | 本地 fixture，且无真实调度器，只有四个可用场景 |
| 运行一条基线 | 选择成功、阻塞、重跑或人工介入场景 | 作业与轨迹标识、最终状态、资源用量与轨迹完整性校验 |
| 审查事件流 | 读取返回的 JSONL | 提交、开始、监控、完成、失败或恢复等事件 |
| 演示中断与恢复 | 使用阻塞或重跑场景 | 可解释的状态转换与 fixture 产物摘要 |

**当前实现范围：** 只有本地 fixture Provider。它不提交外部作业，也不声称支持 Slurm、PBS、Kubernetes 或云调度；真实远程计算请使用 Remote SSH 或终端。

## 典型流程

1. 先查询状态，确认当前提供方是本地 fixture，且没有真实调度器。
2. 选定场景并运行基线，记录轨迹标识、作业标识与最终状态。
3. 检查事件数、轨迹完整性校验与 JSONL，确认事件链完整。
4. 对阻塞或重跑场景核对状态与产物信息，理解重试与恢复的语义。
5. 需要真实计算时，改用 Remote SSH 或终端执行，并把命令、环境、输入与结果带回会话。

## 输入、输出与权限

- 读取：提供方状态；不读取工作区文件。
- 写入：不写工作区；产物路径与校验和只是基线轨迹中的 fixture 描述。
- 审批或外部影响：计算在本地完成，无外部提交，因此不触发审批。
- 不会做什么：不执行命令字符串，不连接集群，不产生真实科学结果，也不把 fixture 状态当作作业调度依据。

## 已知限制

- 仅有四个固定场景；结果是确定性 fixture，适合验证轨迹与流程，不适合评估真实性能。
- 基线轨迹不落盘；需要保留时应在会话或产物系统中显式保存。
- 没有图形面板，也不能从界面直接监控真实队列。
- 阻塞场景返回的是 fixture 诊断，不代表真实作业失败原因。
- Slurm、PBS、Kubernetes 自动调度未声明为内置能力，参见[功能状态与限制](../reference/feature-status.md)。
