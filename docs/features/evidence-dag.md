# Evidence DAG

Evidence DAG 是会话内的证据编译器：它从可见的运行时轨迹中提取主张、来源、运行、产物与关系，并在显式更新或正式边界时编译为不可变证据快照。它回答“这条结论由什么支持或反驳”，位于单次分析之后、项目级汇总与对外交付之前；跨会话汇总由 [Project DAG](./project-dag.md) 负责。

## 打开方式

- 入口：右侧面板 **证据 DAG**；从 Claim、证据快照等资源导航可打开对应会话。
- 作用对象：当前 Runtime 与会话中的已提交证据快照。
- 前提：任务已产生可编译的轨迹，且 Evidence 服务与文本推理配置可用。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 留下可审查的轨迹 | 正常运行任务；工具结果声明 `evidenceLineage` | 运行时轨迹增量 |
| 生成新快照 | 点击 **更新**，等待排队与提交完成 | 不可变 Evidence 快照 |
| 查看主张与证据 | 在图中选择节点，查看来源、运行、产物与关系 | 会话内证据图 |
| 检查溯源断点 | 查看溯源覆盖、断点与限制说明 | 证据缺口清单 |
| 运行结构审计 | 点击 **Audit**，对已提交快照执行只读检查 | L0 审计结果 |
| 下载复跑规格 | 选择 Conclusion 节点，点击 **Download rerun spec** | `.sciforge-rerun.json` 文件 |

## 典型流程

1. 完成一轮分析，让工具结果包含结构化 lineage 与精确产物引用。
2. 点击 **更新**，确认状态从排队、执行中变为已提交。
3. 检查主张到来源、运行、代码、环境与产物版本的完整链路。
4. 对缺失来源、未验证版本、缺少审批等断点做人工确认，不用文字解释补全。
5. 需要跨会话的项目级视图时，转到 Project DAG。

## 输入、输出与权限

- 读取：当前会话可见的运行时轨迹、工具回执、已提交快照、Artifact 版本与来源锚点。
- 写入：证据增量存储、不可变快照与审计侧链；复跑规格从已提交快照导出。
- 审批或外部影响：更新无需额外审批，但会写入证据状态与快照并调用已配置的文本推理服务；复跑规格下载只读。重建是高级操作，必须指定原因并填写理由。
- 不会做什么：不把聊天总结或原始工具回执直接提升为科学产物，不从散文推断缺失元数据，也不改写已提交快照。

## 已知限制

- 功能状态为 **部分可用**：入口已经注册，但只有任务真正产生主张、来源和产物记录时，图才有意义；空面板不是故障。
- 只有已提交快照中的节点和边可用于审计；待处理失败会单独显示，不会让已提交图不可用。
- 主张提升到 L4 需要稳定运行记录、可验证输入、精确软件、参数、环境与日志/产物；随机运行还必须提供随机种子。
- 字段缺失会形成具名溯源断点，不会被推断补齐；内置审计当前执行确定性的 L0 结构检查。
- 重建只用于模式升级、损坏恢复或重新解释，不是日常编辑入口；受限证据的预览会按访问策略失败。
