# Evidence DAG

Evidence DAG 帮你检查一条结论依据什么：在图中查看支持或反驳它的来源、计算步骤、图表与限制。先完成分析并保存来源、结果和相关文件，再点击 **更新** 保存证据图；更新完成后，另行检查图中的关系和缺口。需要汇总多个会话时使用 [Project DAG](./project-dag.md)。

## 打开方式

- 入口：在科研面板点击 **查看证据图**；打开独立证据面板时，从默认的 **研究记录** 切换到 **证据图**。
- 作用对象：当前会话中已保存的证据图。
- 前提：任务已留下来源、分析过程和结果记录，证据图功能及文本推理配置可用。

## 保存和检查证据图

1. 完成一轮分析，保存实际使用的来源、计算记录、结果文件和对应产物版本，明确哪些是结论、哪些仍是假设。
2. 点击 **更新**，等待排队和执行结束，确认新的证据图已保存。更新会调用已配置的文本推理服务，并保存证据记录，无需额外审批。
3. 在图中选择结论和相关节点，逐项核对来源、运行、代码、环境与产物版本是否支持该结论。保存成功后仍需完成这一步审查。
4. 查看溯源覆盖、断点与限制，处理缺失来源、未验证版本或缺少审批的提示。补充真实记录后，再次更新并检查结果。
5. 需要汇总多个会话时，先确认本会话证据图已经保存，再转到 Project DAG 手动更新项目图。

## 进一步核对

- 点击 **Audit**，检查已保存证据图的结构，查看缺口提示。当前审计是 L0 结构检查，结果不能代替科学判断。
- 选择 Conclusion 节点，点击 **Download rerun spec** 下载复跑规格。复跑前还需确认输入文件、软件、参数、环境和相关产物可用；下载规格本身不会执行分析。
- 检查可复现性等级时，重点核对稳定运行记录、可验证输入、软件版本、参数、环境及日志和产物。随机运行还需记录随机种子，才能满足 L4 所需的条件。

## 使用提示

- 尚未保存主张、来源或产物时，图可能为空。先保存分析记录和实际文件，再更新证据图。
- 更新失败时，可以继续查看此前已保存的图，但应确认正在审查的是哪一次结果。只有已保存的图可以用于审计。
- 缺失信息会作为溯源断点提示，不能依靠聊天总结补齐；应回到真实来源和运行记录核对。
- 受限证据可能无法预览，应遵守来源的访问权限。
- 重建只适用于升级、损坏恢复或重新解释，需要指定原因并填写理由；日常补充记录后使用更新。
