# 内容空间

内容空间把不同外部服务中的容器、普通文件和原生文档收敛为同一套访问方式。它本身不保存内容，也不替 Provider 做权限判断；用户看到的是统一的容器与文件入口，实际读写仍发生在外部服务中。

## 打开方式

- 入口：右侧面板的**内容空间**；协作整页的**云盘**区段也复用同一套内容空间能力。
- 作用对象：已连接 Provider 的容器、普通文件与 Provider 原生文档；当前可列出的是思源笔记本。
- 前提：安装并连接一个声明了相应操作族的 Provider；连接通常需要该服务的地址与账号/令牌，内容空间不读取凭据。OpenContent 已退出产品，面向用户目前只有思源 Provider，且仅声明笔记本发现。

## 能做什么

下表是内容空间契约允许的能力。由于当前没有 Provider 向内容空间承接文件传输和原生文档，这些操作会按契约拒绝，而不是返回空结果或假成功。

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 选择空间或容器 | 在内容空间选择已连接 Provider 的根或目录；思源会列出未关闭的笔记本 | 只读容器引用 |
| 浏览与定位文件 | 列出容器条目，并按精确资源引用打开 | 文件或容器视图 |
| 上传或下载普通文件 | Provider 声明传输操作后，经 Host 受限传输在容器与工作区之间复制 | 受 Host 传输上限约束的文件副本 |
| 打开或写入 Provider 原生文档 | Provider 声明原生文档操作后，按目标文档与版本执行 | Provider 中的文档 |
| 管理共享空间与成员 | 仅当 Provider 声明 Administration 时可用 | 成员变更回执 |

## 典型流程

1. 先安装并连接 Provider；连接绑定当前用户与具体 Provider 实例，不能复制给其他用户使用。
2. 打开内容空间，选择 Provider 与容器；思源当前只列未关闭的笔记本，选中后得到只读容器引用。
3. 确认目标路径、影响范围与当前账号权限，再发起读取或写入。
4. 上传、下载和成员变更按界面提示确认；破坏性操作必须每次重新确认，绑定失效或 Provider 拒绝时重新连接，不要反复重试。

## 输入、输出与权限

- 读取：Provider 实例、容器、文件元数据与 Provider 声明的就绪等级；不读取或展示 Provider 凭据。
- 写入：Provider 中的文件、原生文档或成员关系；本机只保留非秘密引用与当前用户的连接绑定。
- 审批或外部影响：普通非破坏性写入可在已授权资源内执行；声明为破坏性的原生文档与扩展操作、成员变更，以及任何破坏性操作，每次都要人工确认，不能沿用上一次批准。
- 不会做什么：不把 Provider 的原生 ACL 换成 Project 成员权限，不在绑定失效后自动回退到另一个 Provider，也不把原始 ID 当作授权。

## 已知限制

- **OpenContent 已退出**：空间与成员管理、上传下载、原生文档不再有 OpenContent Provider 承接；相关能力仍注册，但无可用 Provider 时一律 fail closed。
- 当前思源 Provider 只声明笔记本发现，其余操作返回 `blocked_by_contract`；本地 mock Provider 只用于测试，不是用户功能。
- 就绪等级只是证据，不代表本次调用一定放行；每次调用还会检查当前身份、授权、受众、平台、传输上限和绑定状态。
- 不可变产物引用（`ArtifactReference`）需要不可变保留与精确版本读取证明；当前不满足这些条件时会阻止签发。
- 共享容器成员与 Cloud Project 成员是两套身份边界；Provider 成员不会因此获得 Project 权限。
