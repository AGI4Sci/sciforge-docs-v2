# 图片审改（Visual Review）

图片审改把“这里不对”变成 Agent 能执行的结构化意见。它处在出图与交付之间：人负责指出问题并做最终确认，Agent 负责按标注生成候选版本，插件负责保存批注、审阅包和接受记录。

## 打开方式

- 入口：顶部工具栏 **图片审改** 打开右侧面板；具体审阅从会话中的图片进入。
- 作用对象：当前工作区中的栅格图片、生成图、编辑图、科学图表或演示页图像。
- 前提：工作区可用；一个审阅文档绑定一张源图，从版本化产物打开时会校验摘要与字节长度。生成候选版本需要 Runtime 与图像生成 MCP；只批注和导出审阅包不需要外部服务。

## 能做什么

| 你要完成的事 | 怎么做 | 产出 |
| --- | --- | --- |
| 指出要改哪里 | 用 **框选**、**箭头**、**圈画**、**图钉** 标注，并填写修改建议 | 结构化批注 |
| 把意见交给 Agent | 点击 **生成修改版**；插件保存批注、导出审阅包并发送修改请求 | 候选版本 |
| 比较修改前后 | 用 **修改前**、**修改后**、**分割对比**、**叠加对比** 检查候选 | 差异判断 |
| 接受或拒绝 | **接受并替换** 或 **拒绝** | 新版本或保持源图 |
| 统一视觉风格 | 在 **图像风格识别** 中选择参考图 | 绑定到文档的论文视觉规范 |

## 典型流程

1. 从会话中的图片打开 **图片审改**，确认源图和工作区；如来自版本化产物，确认绑定的版本。
2. 选标注工具圈出问题，逐条填写修改建议；处理完的批注可标记为已解决。
3. 点击 **生成修改版**。插件会把批注保存为审阅包，并在当前会话中发出带约束的修改请求。
4. 候选版本生成后自动进入对比界面。检查裁切、重叠、标签可读性、数据与未标注区域是否被误改。
5. 确认无误后点击 **接受并替换**；需要重做则点击 **拒绝**。接受后源图被替换，旧图保留修订备份。

## 输入、输出与权限

- 读取：工作区栅格图片、审阅文档、绑定的 Artifact Version、已有批注与候选版本。
- 写入：审阅文档与批注、审阅包；接受候选时先提交 Artifact Version，再原子替换源图并保留备份。
- 审批或外部影响：**接受并替换** 是破坏性操作，必须确认；生成候选会调用 Agent/图像生成链路，可能产生模型调用与费用。
- 不会做什么：不自行生成或编辑图片；候选未接受前不覆盖源图；不解析文档排版或矢量源文件。

## 已知限制

- 只支持有界栅格图片（常见 PNG/JPEG/WebP 等）；演示页也按图片审阅，不提供元素级编辑。
- 候选版本必须由 Agent/图像生成链路产出并通过候选 QA；本插件不提供“直接修图”按钮。
- 同一文档当前只展示一个活动候选版本；要换方案需先接受或拒绝现有候选。
- 接受后下游文档不会自动重编译；插件会提示 Agent 重新编译并检查引用。
