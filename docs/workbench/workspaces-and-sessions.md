# 工作区与会话

工作区决定 Agent 在哪里读取文件、查看 Git 和运行命令；会话保存围绕一个目标的消息、执行与结果。同一个工作区可以有多个会话。

## 认识当前布局

- **左侧边栏**：组织工作区、会话以及扩展提供的导航。展开后可查看协作项目、我的工作与收件箱；底部是本地账户、云端状态、用量摘要和设置。
- **中间会话区**：查看任务、工具调用和回答，在底部输入任务。
- **最右侧纵向工具栏**：打开文件等面板；空间不足时通过“更多工具”查找入口。工具的显示取决于安装和可用状态。
- **停靠面板**：支持停靠的页面可放在左侧、右侧、底部或主区域；会话右侧面板还可按支持情况拆分、调整宽度、切换内容及前进后退。两类布局不是同一个开关。

侧边栏收起后不显示完整的账户摘要与项目树；需要这些入口时先展开。

## 打开工作区

1. 在工作区位置菜单中选择本地工作区或已配置且可用的目标。
2. 选择论文、代码或数据所在目录。
3. 核对工作区路径与侧边栏项目名称，再创建会话。
4. 新目标使用新会话；继续同一目标时沿用原会话。

## 加入文件：选择、拖放、粘贴或引用

输入区的 **添加文件** 打开文件选择器，也可以把受支持的文件拖入输入区，或粘贴剪贴板中的文件、图片。普通文本粘贴仍作为文本处理。PDF、图片、科学数据和网页文档按各自类型与大小规则检查；不支持或导入失败时会显示错误。

从最右侧工具栏打开 **文件** 面板，可浏览、预览并引用工作区对象。输入 `@` 也可查找工作区文件；带空格的引用使用 `@"目录/文件名"` 形式。

发送前，输入框上方的**附件托盘**集中列出待发送对象、类型、路径与已知大小。可预览支持预览的引用，或移除本次不需要发送的条目。发送后，用户消息下方的**已发送文件标签**保留文件名和已知大小，点击可预览对应工作区文件；它不是可继续删改的待发送清单。

| 输入形式 | 当前实现的处理 | 需要理解的边界 |
| --- | --- | --- |
| 工作区已有文件 | 保留工作区相对路径引用（path reference） | 文件内容不会因为显示了附件标签而整体嵌入模型提示；Agent 按需调用工具读取 |
| 从工作区外选入或粘贴的受支持文件 | 导入工作区的会话附件目录，再作为路径引用 | 导入会写入工作区；移除待发送条目不等于删除已导入的文件 |
| 支持的模型图片附件路径 | 通过 Runtime 附件能力处理图片；具体输入受 Runtime、模型与图像处理配置约束 | 与工作区路径引用不同，可能涉及嵌入图片或图像转换；不能据文件标签断言模型已直接读取原图 |

当前工作台在存在工作区时优先将图片也保存为工作区引用。不要把“添加文件”理解为把整个目录同步到云端，或保证模型已经理解文件内容。只读演示应直接引用已有文件，避免额外导入造成文件变更。

## 管理会话与审查变更

点击会话继续目标，使用搜索查找历史记录，归档暂时不用的会话并按需恢复。删除前将重要结果保存到工作区或科研记录。不要用一个会话混合互不相关的科研目标。

修改文件后，可让 Agent 使用 [Change Inspector](../features/change-inspector.md) 核对本次会话的改动，再运行 `git status --short` 查看整个工作区。关闭面板或切换会话不会撤销文件修改。

一个清楚的会话开头：

> 阅读当前工作区的 README、依赖配置和主要入口。先给出最短运行与测试路径，不要安装依赖或修改文件；无法确认的内容单独列出。
