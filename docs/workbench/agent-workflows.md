# 与 Agent 协作

写清目标、允许范围、交付物和停止条件，让 Agent 的每一步都能检查。

## 一个可执行任务的四部分

| 部分 | 要回答的问题 | 示例 |
| --- | --- | --- |
| 目标 | 最终要解决什么问题？ | 找出测试失败的根因 |
| 范围 | 可以读取和修改哪里？ | 只看当前包，不改公共 API |
| 约束 | 哪些动作不可自动执行？ | 不安装依赖，不访问外网 |
| 验收 | 怎样证明已经完成？ | 相关测试通过，解释根因与改动 |

推荐模板：

```text
目标：……
范围：……
约束：……
交付物：……
验收方式：……
遇到以下情况请停止：……
```

## 先读、再计划、后写入

对于陌生项目或科研数据，推荐分三轮：

1. **只读分析**：让 Agent 建立项目、数据和风险基线。
2. **计划审查**：检查拟修改文件、输出路径、依赖和验证方法。
3. **执行与验证**：切换到合适权限，完成写入并审查差异。

## 核对输入文件

通过输入区的 **添加文件**、拖放、粘贴或文件引用加入材料。发送前在附件托盘核对文件名、路径与类型，移除不需要发送的条目；发送后从消息下方的文件标签打开预览。

工作区路径引用让 Agent 按需读取文件，不会自动把文件全文嵌入提示。外部文件导入会写入工作区；只读任务应引用已有文件。具体操作见[工作区与会话](./workspaces-and-sessions.md)。

## 查看执行过程

执行过程中重点检查：

- Agent 当前处理的步骤
- 实际读取的文件
- 工具调用及参数
- 命令、返回码和输出
- 写入文件与目标路径
- 等待用户决定的审批请求

批准前检查操作对象、影响范围、外部目标和恢复方式。需要查看文件或差异时，从最右侧纵向工具栏打开面板；支持停靠的页面可移到侧边或底部，与会话并排查看。

协作任务中的提问由指定成员回答；动作确认需要填写说明并明确批准或拒绝。提交决定后继续查看执行结果，最后由成员审阅交付、负责人采纳。参见[协作](../features/collaboration.md)。

## 修正不完整结果

不要只说“再详细一点”。引用具体缺口：

> 你列出了入口文件，但没有说明从启动到主界面的调用链。继续只读分析，按调用顺序列出函数和源码路径；推测内容单独标注。

## 长任务的切分

把长任务分成可以独立验收的阶段，每个阶段写清输入、输出与停止条件。科研任务尤其应在数据审计失败时停止，而不是继续生成看似完整的图表和报告。
